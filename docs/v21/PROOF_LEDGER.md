# 证明与检查台账：分清四种证据

时间：2026-11-16　对象：`rtl/v21/recon_v21.sv`
基线：`a9fe12e`

本文件把所有"证明"按证据类型分开，**不把一种证据当另一种用**。

## 0. 三类证据，不能互相替代

| 类型 | 证明什么 | 不证明什么 |
|:---|:---|:---|
| **[A] 数学公式证明** | 一个恒等式在给定前提下的全称成立 | 生产 RTL 是否真的实现了它 |
| **[B] 生产 RTL 检查** | 生产源码当前的实现与规格逐点一致 | 规格本身是否正确 |
| **[C] 工具形式化** | 第三方工具独立确认 | 目前未完成 |

早前的错误是把 [A] 的结论写成"生产 RTL 已证明"。审查方在隔离副本里
改错生产常数后脚本仍打印 PROVEN，暴露的就是这个问题。

## 1. [A] 数学证明：`RND(n, 96)` 的常数除法

**命题**：设 `m = ceil(2^34/3) = 0x1_5555_5556`，则对 `|n| < 2^31`，
`floor(|n|·m / 2^34) == floor(|n|/3)`。

**证明**：
```
m = 0x1_5555_5556 = 5,726,623,062
注意 m 最少需要 33 位无符号 —— [33:0]（34 位）本来就能装下。
（早前把事故归因写成"需要 35 位、34 位装不下"是错的，已订正。）

3m - 2^34 = 2
设 a = 3q + r（0 <= r < 3）：
  a·m/2^34 = q + (2q + r·m)/2^34
需要 0 <= 2q + r·m < 2^34。
上界：2q + r·m <= 2·(2^31/3) + 2m = 12,884,901,888 < 17,179,869,184 = 2^34  ✓
```
**这是不等式给出的全域结论。** 点集检查（等价类端点 + 均匀 + 随机）
只是补充核对，不构成证明的一部分。

**前提**：`|n| < 2^31`。本命题**不**自动保证生产代码把 `X_wide`
截成 32 位是安全的 —— 那需要另证，见 §3。

## 2. [B] 生产 RTL 检查（`tools/check_rtl_rnd96.py`）

**做法**：从 `rtl/v21/recon_v21.sv` **原地读取**
`rnd96_const` 函数体与 `MAGIC_3_34` 常数（不复制、不重写），
包成可仿真模块，用 VCS 逐点比对。

**记录**：脚本打印源码 `sha256`、抽取到的常数字面值、函数体行数、
检查点数。当前：

```
源码: rtl/v21/recon_v21.sv
sha256: d78cf45a4587873ed08a49ca031ac6952f5a6d7312c7605527d9acc8bedaf564
抽取到 MAGIC_3_34 = 35'h1_5555_5556
检查点 74618 个
失配 0
RESULT: RTL_CHECK_PASS
```

**结构自检**：抽取时要求函数体里必须出现 `>> 34`、`>> 5`、
`* 32'd96`、`>= 32'd96`。少任何一个都直接报错，
防止函数被替换成别的实现而检查仍然"通过"。

## 3. [B+] 变异测试（`tools/check_rtl_mutation.sh`）

**这是关键**：一个"改错了也不报"的检查等于没有检查。

| 注入 | 预期 | 实测 |
|:---|:---|:---|
| 常数 `35'h1_5555_5556` -> `34'h5555_5556`（历史真实事故） | FAIL | **FAIL** |
| 移位 `prod >> 34` -> `prod >> 33` | FAIL | **FAIL** |
| 舍入阈值 `>= 32'd96` -> `>= 32'd95` | FAIL | **FAIL** |
| 恢复原始 RTL | PASS | **PASS** |

全部符合预期。所以 §2 的 PASS 是有区分力的 PASS。

## 4. [A] 数学证明：`X` 的 32 位截断无损（`tools/prove_xwidth.py`）

recon 把 96 位的 `X_wide` 截成 `$signed(X_wide[31:0])`。
这一步只有在 `|X| < 2^31` 时无损。

**假设（每条注明来源）**：

| 编号 | 假设 | 来源 |
|:---:|:---|:---|
| A1 | `raw ∈ [0, 8191]` | 13 位 ADC2 码，接口位宽保证 |
| A2 | `alpha ∈ [2^29, 2^31]` | 方案 §9.2 profile；RTL 的 `bad_alpha` 按此域报 `err` |
| A3 | `\|b\| <= 2^26` | `b_q24` 是 signed 27 位 Q24 |
| A4 | `G ∈ [16·2^30, 64·2^30]` | 方案 §9.2 profile |
| **A5** | **每个 `w_sub <= 4·2^30`** | **合同未给此上界**，本证明取"单列满量程 4Cu"作保守假设 |

**推导**：
```
Y ∈ [-3,144,960, 9,436,416]
|Y-b| <= 76,545,280
|Z| = RND((Y-b)·2^30, alpha) <= 153,090,561        (alpha 最小时最大)
Wm, Wp <= 8 片 × 4 位 × 4Cu = 137,438,953,472 = 128 Cu
|N| = |Z·64 + 6Wm - 3G - 6Wp| <= 1,865,223,667,776   (41 位)
I = RND(2^60, G) <= 67,108,865                       (27 位)
|N·I| <= 1.2517e20                                   (67 位)
|X| = |N·I| >> 36 <= 1,821,507,515 = 0x6C91FFBB      (31 位)
```
`1,821,507,515 < 2^31 = 2,147,483,648`，用掉 84.82%，余量 15%。

**RESULT: XWIDTH_PROVEN**

**必须记录的一条**：早前用"有限角点最大值 353,632,160"作为依据，
它比真实上界小 **5.2 倍**。角点法不是全域界，不能作为位宽依据。

**A5 是这条证明的软肋**：合同没有给权重表数值上界。
若实际权重表允许某列超过 4Cu，本证明失效，必须更新 A5 后重跑。

## 6. 域外行为（明确不覆盖）

上面的证明都限定在合法域内。域外输入由 RTL 的 `err` 标志负责：

- `bad_g`：`G == 0`
- `bad_alpha`：`alpha` 越出 `[2^29, 2^31]`
- `bad_epoch`：`in_epoch != cfg_epoch`

**不能声称"现有 err 已覆盖所有域外输入"** —— 例如 `Wm`/`Wp` 超出 A5
假设时并没有专门的 err 检查，只是位宽证明不再成立。
这是一个已知的合同缺口，列在待办里。
