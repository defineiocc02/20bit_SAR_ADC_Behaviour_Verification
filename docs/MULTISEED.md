# 多 seed × 多频统计（D3 / ADC2 窗口）

工具 `tools/multiseed.py`（已入库，可复现）。
N=17280，amp=1.5 V，freqs = {691, 1093, 2417}，seeds = {2026, 7, 99, 1234, 555}，
每档 = 5 seed × 3 频 = **15 组 × 17280 笔**。

逐笔按自己的 `(x, group, phase, k)` 算一次电荷，用 `(g,res,hp,vp,k)` 缓存，
不预计算全状态 512 码。

## 汇总

| 失配档位 | 负向溢出 | 正向溢出 | 有效转换 |
|:---|:---|:---|:---|
| **压力 1% / 1.5% / 2.5%** | **13.29 ± 2.50 %** | **5.65 ± 1.77 %** | **81.05 ± 4.24 %** |
| **目标 0.1% / 0.15% / 0.25%**（假设） | **1.55 ± 0.31 %** | **0.00 ± 0.00 %** | **98.45 ± 0.31 %** |

| 691 | 1.59% | 0.00% | 98.41% | −1.03 mV | +12.63 mV |
| 1093 | 1.58% | 0.00% | 98.42% | −0.93 mV | +12.72 mV |
| 2417 | 1.82% | 0.00% | 98.18% | −1.05 mV | +12.68 mV |

## 读法

1. **压力档有 81% 有效、19% 溢出**，跨 15 组波动 ±4.2%——结构风险是稳定的，不是个别 seed 的偶然。
2. **目标档正向溢出恒为 0**（15 组全部 0.00%），
   说明正向余量在 14.06 mV 窗口下够用。
3. **目标档负向溢出稳定在 1.55 ± 0.31%**，
   即真实余差最小值约 −1.0 mV，落在窗口下界 0 之外。
4. 频率对结果影响很小（691/1093/2417 三档差异 < 0.3%），
   说明溢出由码/相位分布决定，不由输入频率决定。

## 边界

- 「目标档」的 0.1% / 0.15% / 0.25% 是**假设值**，论文未公开实际单元匹配。
  它只用于说明"失配量级 → 余差需求"的趋势，**不能当作 ADI 原芯片水平**。
- 因此准确表述是：**在本工程的单边 ADC2 窗口假设与当前失配模型下**，
  压力档有效率 81%，目标档 98.5% 但存在约 1% 的负向溢出。
  **不推断 ADI 原芯片也有此问题。**

## 28 nm Hold 违例路径归类

`hold_fix.rpt` 前 5 条违例路径**全部**是：

```
tag_b_reg[0..4]  →  tag_s1_reg[0..4]
```

即 **tag 流水线**（`tag_a → tag_b → tag_s1 → tag_s2`）的纯寄存器直连，
中间几乎没有组合逻辑，因此整条流水线的每一位都容易 hold 违例。

118 条违例以此为典型代表，说明主因是**流水线直通路径过短**，
而非某个复杂逻辑块。

处理方向（未实施）：合并流水级、增加有效逻辑延迟、或 CTS 后由时钟 skew 吸收。
**不把 hold 失败归因于"理想时钟"** —— CTS 前用理想时钟是常规做法；
真实判断要在 CTS 后用实际插入延迟重做，且**不保证违例自动消失**。
