# 关键缺陷二：`wsum_v21` 的输出被综合成常数 0

时间：2026-11-16　基线：`1fb9408`
发现途径：权重表随机值扫描（不是 Formality，也不是名义权重的门级 e2e）

## 1. 结论

**`wsum_v21` 在综合网表里输出恒为 0。** 这是真实功能缺陷，
与 `recip_q60` 的 LUT 问题属同一类（综合把数据通路常量折叠）。

## 2. 铁证：最小用例

激励：`wm[0][0] = 1024`，`post[0] = 1`，其余全 0，`ids` 全 0。

| 侧 | G_q30 | Wm_q30 | 说明 |
|:---|--:|--:|:---|
| **RTL** | **8192** | **1024** | 正确（`f_G` 累加 8 slot × 1024） |
| **网表** | **0** | **0** | **完全错误** |

单权重、单 bit 选中，最简单的情形，网表直接输出 0。

## 3. 网表里的直接证据

```verilog
TIELBWP7T40P140 U3 ( .ZN(net1700998) );      // 恒 0

assign G_q30[63] = net1700998;
assign G_q30[62] = net1700998;
assign G_q30[61] = net1700998;
...                                          // 高位全部同接一根恒 0 网
```

`G_q30` / `Wp_q30` / `Wm_q30` 的多个 bit 被同一个 TIE-LOW 驱动。

## 4. 随机权重扫描（256 组）

见 `tb/v21/tb_wsum_scan.sv` + `tools/gen_wsum_gate_tb.py`。

| 指标 | 值 |
|:---|--:|
| RTL 记录 | 256 |
| 门级记录 | 256 |
| 剔除 X 后共同记录 | 255 |
| **G 不符** | **226 / 255** |
| **Wp 不符** | **255 / 255（100%）** |

权重表取 `[1, 2^30]` 随机值（低 4 位强制非零，专打 Formality 报的低位 bit）。

**已排除的可能**：
- 位序打包错误 —— 从网表端口声明读出拼接首位 `\w_main_tbl[0][0][39]`、
  末位 `\w_main_tbl[17][15][0]`，与打包 `(s*16+j)*40 +: 40` 一致
- X 污染 —— 剔除含 X 的记录后仍 226/255 不符
- 测试台期望值错误 —— 首个 smoke 用例我的期望值写错了（以为 G 是单 slot，
  实际 `f_G` 累加 8 slot），修正后 RTL 表现正确，说明 TB 没问题

## 5. 为什么此前所有验证都没抓到

| 验证 | 为什么漏 |
|:---|:---|
| `tb_i4b_e2e`（25 项） | RTL 级；且权重表是**名义固定值** |
| `check_gate_e2e`（1890 拍差异 0） | **同样只喂名义权重**（`268435456` 等） |
| RTL 回归 8 项 | 全是 RTL 级 |

**关键缺口**：名义权重下一个特定组合，恰好不暴露这个常量折叠。
只有给权重表**任意值**才看得出。

## 6. 与 Formality 的关系

Formality 报 `u_wsum` 的 20 个 failing：

```
G_q30_reg[3,4,5,6,8,12,13,18]    8 个
Wp_q30_reg[0,2,8,10,13,15]       6 个
Wm_q30_reg[0,2,6,11,14,15]       6 个
```

**这个结果是对的，不是工具问题。** 子代理曾倾向"数组端口可追溯性问题"
并把 `set_constant` 的诱惑拒掉 —— 那个判断在方法上是对的（不该裁输入域），
但**结论需要修正**：网表确实错了。

`analyze_points` 报 2833 个"未约束端口"全是权重表 —— 那是因为
**这些端口在实现侧被常量折叠后不再影响输出**，Formality 因此认为它们
"未被约束到",而不是名字匹配问题。

## 7. 根因假设（待验证）

`wsum_v21` 的 `f_Wm`/`f_Wp`/`f_G` 是**函数内读二维数组端口**。
DC 可能因为以下原因把它们折叠：

1. `w_main_tbl` / `w_sub_tbl` 是**未在 top 层面驱动的输入端口**
   （在 `adc_digital_ip_v21` 里由顶层端口直通），DC 在某些路径分析下
   把它们当常量
2. 函数内读数组 + 循环变量索引，DC 的 `set_ungroup` / 边界优化把锥切断
3. 与 `recip_q60` 同源：某个 `initial` 或常量传播把权重表变成已知值

**验证方法**：查 `dcwork4/dc.log` 里 `w_main_tbl` 的 OPT-1206 记录。

## 8. 下一步

1. 查 DC 日志里权重表端口是否被报为常量
2. 若确认，修法是把 `f_Wm`/`f_Wp`/`f_G` 的数组读取改成显式 case 或
   保证端口不被常量传播
3. 重综合后重跑：随机权重扫描 + 门级 e2e + Formality

## 10. 根因锁定（补充：逐 slice 扫描）

### 10.1 扫描方法

对 `wsum_v21` 网表，固定 `ids=0`、`post[0]=1`，逐个把 40 位 slice 置全 1
（`wm_f[s*40 +: 40] = 40'hFFFF_FFFF_FF`），看 `G_q30` 是否有响应。

### 10.2 结果

| slice 范围 | 对应 `w_main_tbl[sid][j]` | `G_q30` 响应 |
|:---|:---|:---|
| 0 – 271 | `sid = 0..16` | **全部 0**（无响应） |
| **272 – 287** | **`sid = 17`, `j = 0..15`** | 有响应 |

**288 个 slice 中只有最后 16 个（`sid=17`）有效。**

### 10.3 数字精确验证

```
全部置 1（wm_f = ws_f = 1，post 全 1，ids=0）：
  G = 140,737,488,355,200
  8 × 16 × (2^40 − 1) = 140,737,488,355,200
```

**完全相等。** 说明 `f_G` 实际只累加了 `sid=17` 那一行的 16 列 × 8 slot，
`sid=0..16` 的 17 行全部被折叠掉。

同一测试里 **`Wp = 0`**（`post` 全 1、`ws_f` 全 1 时应非零），
说明子阵列路径也被折掉了。

### 10.4 这解释了全部现象

| 现象 | 解释 |
|:---|:---|
| 最小用例 `wm[0][0]=1024`（`sid=0`）→ `G=0` | `sid=0` 被折掉 |
| 随机权重 256 组，`G` 不符 226/255 | 8 个 slot 的 `ids` 随机落在 0..17，只有落在 17 的才被算 |
| `Wp` 不符 **255/255（100%）** | 子阵列路径整体失效 |
| `dc.log` 里 `G_q30_reg[52..59]` 等被 `OPT-1206` 删除 | DC 认为高位是常量 |
| 网表里 `TIELBWP7T40P140 U3 (.ZN(net1700998))` 驱动 `G_q30` 高位 | 常量折叠的直接痕迹 |

### 10.5 为什么只有 `sid=17` 幸存

最可能的原因：**数组越界/索引位宽问题**。

```systemverilog
input  logic [39:0]  w_main_tbl [0:17][0:15],   // 18 项
acc = acc + {24'd0, w_main_tbl[ids[s*5 +: 5]][j]};   // ids 是 5 位（0..31）
```

`ids` 是 **5 位**，可表示 0..31，但数组只有 18 项（0..17）。
DC 在做常量传播时，对越界索引（18..31）的行为未定义，
可能把所有 `sid` 都当作越界后折叠到同一个值 —— 而 `17` 是最后一个合法下标。

**待验证**：在 RTL 里把 `ids` 钳位到 `[0,17]` 后重综合，看是否恢复。
但这只是修法之一；也可能 DC 对"函数内读二维数组端口"本身处理有问题。

### 10.6 这是本轮第二个真实功能缺陷

| 缺陷 | 表现 | 状态 |
|:---|:---|:---|
| `recip_q60` LUT | `i_q60` 恒为常数 2 | ✅ 已修（`878a348`） |
| **`wsum_v21` 权重求和** | **只有 `sid=17` 有效，其余 17 行全折掉** | ❌ **未修** |

**两个都是"仿真通过、综合出错"**，都只能靠门级或形式化发现。

## 11. 钳位修复的安全性论证（合法域不受影响）

### 11.1 钳位逻辑

```systemverilog
function automatic logic [4:0] sid_of(input logic [39:0] ids, input int s);
    logic [4:0] v;
    begin
        v = ids[s*5 +: 5];
        sid_of = (v > 5'd17) ? 5'd17 : v;   // 只在越界时钳
    end
endfunction
```

`v <= 17` 时**原样返回**，只有 `v > 17` 才钳到 17。

### 11.2 上游合法域

`sched18` 的片号由 `pick()` 产生：

```systemverilog
function automatic logic [4:0] pick(input logic [17:0] v,
                                    input logic [4:0] pc [0:17],
                                    input int n);
    logic [4:0] r;
    begin
        r = 5'd0;
        for (int i = 0; i < 18; i++)
            if (v[i] && (pc[i] == 5'(n))) r = 5'(i);   // i ∈ [0,17]
        pick = r;
    end
endfunction
```

**`pick` 的返回值 `r` 只能是 0 或某个 `i ∈ [0,17]`** ——
循环上界是 18，赋值来源是 `5'(i)`。

所以合法域内 `ids ≤ 17` 恒成立，**钳位分支永不触发**。

### 11.3 实测验证

改前 vs 改后的 RTL 在 256 组随机权重扫描下：

```
差异 0 处
```

（测试的 `ids` 由 `(seed + s*3) % 18` 生成，全部在 0..17 内。）

### 11.4 结论

**钳位不是"为了让综合通过而改功能"**，而是：
- 合法域内：零行为改变
- 越界时：把"综合器的未定义行为"变成"确定值 17"

后者是健壮性改进 —— 越界输入本就不该出现（上游保证 ≤17），
但让它在综合后有一个确定行为，比让 DC 折叠掉 17/18 的权重行好得多。
