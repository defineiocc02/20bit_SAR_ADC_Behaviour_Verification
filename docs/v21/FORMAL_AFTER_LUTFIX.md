## 5. 关键观察：门级等价与 Formality 结论不一致

| 验证 | 结论 |
|:---|:---|
| 门级 e2e（两笔完整事务，1890 拍） | **差异 0**，RTL == 网表 |
| Formality | `Wm_q30`/`Wp_q30` **20 个 bit 不等价** |

这**不矛盾**：门级只覆盖施加的两笔激励（A/B 的特定 raw 与权重），
而 Formality 探索所有输入组合。`Wm_q30`/`Wp_q30` 的值在不同的
`ids_i` / `pre_mask` / `post_mask` 组合下才暴露差异。

**因此不能因为门级过了就认为 `wsum` 没问题。**

## 6. 发现的潜在 RTL 健壮性问题（未修，待确认）

`wsum_v21` 的数组维度是 `[0:17]`（18 片），但索引来自 `ids_i[s*5 +: 5]`
——**5 位可表示 0..31**。若片号 ≥18，就是越界读。

```systemverilog
input  logic [39:0]  w_main_tbl [0:17][0:15],
input  logic [39:0]  w_sub_tbl  [0:17][0:3],
...
acc = acc + {24'd0, w_main_tbl[ids[s*5 +: 5]][j]};   // ids 是 5 位
```

- 合同上片号应 ≤17（18 片三态池），上游 `sched18` 保证
- 但 **RTL 没有显式钳位**，形式化工具会探索 18..31
- 这**可能**是 `Wm_q30`/`Wp_q30` 失败的原因，也**可能**不是

**需要 `analyze_points` 才能确认，本轮未取得。**

## 7. 下一步（按优先级）

1. **对 20 个 failing 跑 `analyze_points -failing`** —— 唯一可靠手段。
   若指向 `ids_i` 越界，则加钳位（`ids > 17 ? 0 : ids`），这是**真实的
   RTL 健壮性修复**，不是为了让 Formality 通过而裁输入域。
2. 若指向别的，按证据处理。
3. 无论结论如何，**不能**通过加输入域约束来"消除"这 20 个点，
   除非能证明合同明确且上游保证。
