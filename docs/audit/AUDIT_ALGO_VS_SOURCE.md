## 2. 关键发现：ADC2 位数

### 2.1 §9.3 的常数反推出 13 bit

```
Y = -3145728 + 1536*adc2_raw + 768
```

反推：

| 量 | 值 |
|:---|:---|
| `YMIN = -3145728` 按 Q24 | **-0.1875 V** |
| `SLOPE = 1536` 按 Q24 | **9.1552734375e-05 V/LSB** |
| 满量程 = 8192 × SLOPE | **0.75 V** |
| 窗口 | **[-0.1875, +0.5625) V** |
| 位数 | **13 bit**（8192 码）|

**这与 v21 RTL 的 `adc2_node_macro.sv` 完全一致。**

### 2.2 14 bit / 0.45 V 的斜率不是整数

```
ymin = -0.0375 V  -> Q24 = -629146      （整数 ✓）
lsb  = 0.45/16384 -> Q24 = 460.800000   （非整数 ✗）
```

**所以 14 bit / 0.45 V 无法用 §9.3 那种整数形式表达。**

### 2.3 真正的结论

| 对象 | ADC2 配置 | 与 §9.3 常数的一致性 |
|:---|:---|:---|
| **方案文档 §9.3** | 13 bit / 0.75 V（反推） | — |
| **v21 RTL** | 13 bit / 0.75 V | **一致** |
| **Python 模型** `defaults.py` | **14 bit / 0.45 V** | **不一致** |

**Python 模型是"外来者"，不是 RTL。**

### 2.4 但 Python 那边有理由

`defaults.py:100`：

```
# 结果二级量化 LSB 折到输入 = 0.60 LSB20，单这一项就吃不满 20 bit 目标（需 ≤0.5）。
# 14 bit 时该值 = 0.15 LSB20 ✓。
```

即：**13 bit 时二级量化误差 0.60 LSB20 > 0.5（吃不满 20 bit），14 bit 时 0.15 LSB20。**

**这是真实的系统级矛盾**：
- 选 13 bit → 与 §9.3 常数的整数性相容，但二级量化误差超标
- 选 14 bit → 满足 20 bit 目标，但 §9.3 常数不是整数形式

**这个矛盾我无法自行裁定，需要人判断。**
