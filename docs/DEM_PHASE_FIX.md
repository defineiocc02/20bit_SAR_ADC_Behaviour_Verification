# DEM 相位锁定：已落地

## 问题

`reserved = sid % 16`、`h_phase = sid % 15`、`v_phase = sid % 8` 三者同源取模，
联合周期只有 720 笔。实测 `k=4`（纯纵向选择）时，**每个物理片只覆盖 16 列中的 8 列**，
且 720 笔后重复，继续跑也不会补齐。

## 修法（工程候选，非 ADI 原序列）

```python
q = sample_id // 9                       # 每 9 笔完成一轮 18/8 调度
reserved = q % 16
v_phase  = (q // 16) % 8
h_phase  = (q // 128) % 15
```

完整周期 = 9 × 16 × 8 × 15 = **17280 笔**。片选算法不变。

## 落地位置

`src/adi_model/digital_chain.py` 的 `dem_phases(sample_id)`，`run_transaction`
与测试共用同一份推导。提交 `cab82ff`。

**关键点：共用 `dem_phases()`，不要在别处再写一份相位推导。**

上一轮改动失败，根因不是相位公式，而是**测试里的 `_gk()` 又写了一份相位推导**：
两份推导在相位变化后不再一致，`test_weight_calibration_closes.py` 报真系数误差
3990 µV，被误判成"改动本身有问题"而回退。现在测试直接从 `digital_chain`
导入 `dem_phases`，两份推导漂移这个根因被消除。

## 实测

跑满 17280 笔，`k=4` 时：

```
每片覆盖列数 = [16, 16, 16, 16, 16, 16, 16, 16]     （原为 8/16）
```

覆盖问题确实解决了。

## 边界

- 这是**覆盖**问题，不是打乱质量：排程仍是逐笔旋转的工程候选，
  与 US10511316B2 的两级 shuffler 不是同一结构，不能声称"DEM 已按原序列实现"。
- 相位改动后旧向量作废。向量重生成时**必须用 DUT 返回的实际 `slice_ids`**，
  不能硬编码片 ID（此前硬编码导致 361/400 失配）。重生成后 VCS `recon_d5_w`
  **400 组 0 失配**（`e665dff`）。
