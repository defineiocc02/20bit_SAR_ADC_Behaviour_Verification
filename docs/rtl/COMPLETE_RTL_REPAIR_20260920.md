# RTL 完整修复与综合复核（2026-09-20）

范围：PR #3 中全部 16 个 RTL 模块，保持顶层端口、16 相位节拍与重构数值契约。
本轮相对 `85b4b49` 继续修复；此前问题、综合脚本修复见
[首次报告](REVIEW_20260919.md) 与 [综合专项报告](RTL_SYNTHESIS_REVIEW_20260920.md)。
行为变更以 [ADR 0017](../adr/0017-rtl-fixed-phase-capture-and-structure.md) 为准。
这里的“完整”表示逐模块检查并修复本轮确认的问题，不等同于形式证明或物理签核。

## 2. 验证方法与结果

运行 `python tools/run_open_rtl.py`，不修改黄金期望值，不缩减全码空间。
P2 全码 oracle 分离到专用 TB 以减少无关大阵列的调度开销；仍检查全部
1,048,576 个输出码和每次转换延迟。

新增三套回归：

- `review_leaf_tb`：91,142 次检查，覆盖轨数、参数、权重末地址、计数器回绕、
  除零、负数 floor、忙时输入变化及不同除法展开数。
- `review_recon_protocol_tb`：未配置 start、配置撤销后重新使能无旧结果泄漏、
  正常恢复、非法索引保持与 gain_err 清理；撤销与除法完成同拍不泄漏错误事件。
- `review_top_protocol_tb`：原子控制中断、非法读写、抖动模式互斥、ready 丢失、
  截止沿后输入扰动、模拟标志错相位扰动、完整 epoch 清理。40 个计划样本中
  丢弃两个缺 ready 样本，精确得到 38 个输出。另用未强制注入的两个 dither
  模式独立计算整数重构公式并比较实际输出。

P3 的模拟标志现在与该行数据一起驱动，删除“在下一样本中途驱动上一行标志”的
旧补丁。P3 保留外部 PCG64 dither 向量的层次化注入，因此 P3 自身仍不是片内
随机源到模拟注入的闭环证明；新模式 TB 另行验证片内源的数字路由和整数结果。

生产 RTL 的 lint 单独执行，不用测试台宽度警告掩盖设计宽度问题。两套顶层
`sar20_digital_core`、`sadc_enc` 的当前 lint 无警告；指定结构/宽度警告升为错误。

本机 Verilator 安装包标识 5.48.0，运行 banner 为 5.49 开发构建；保留实际
`version.log`，不混称正式 5.48/5.49 release。GitHub 使用 Ubuntu 24.04 自带
Verilator 5.020。完整 Python 回归 571 passed、3 deselected（远程 slow）；ruff、format、mypy 与
Bash 语法检查通过。最终运行计数与日志摘要见 `evidence/complete_rtl_repair_20260920.json`。

负对照方法：保留新增测试及其余当前 RTL，分别仅恢复 `85b4b49` 的
`unit_therm`、`slice_alloc`、`recon_core`。要求成功编译后由特定功能断言失败；
编译错误或环境异常不算检出。对应断言分别为 signed rail count、counter wrap、
unconfigured start。具体退出码和日志摘要随证据保存。

## 3. 综合仍需解决的实际问题

本次使求和、popcount 和 bank 选择结构明确，并去掉除法动态取位。没有增加流水拍。
综合器可能已对部分旧表达式作等价优化，故这些结构变化不能直接换算成面积/频率改善。

- 权重仍为 18×71×48 = 61,344 bit 寄存器阵列，另有完整性 bitmap 和控制寄存器。
  仍保留复位与宽并行读，不声称已推断 SRAM。换 SRAM 需明确端口、带宽及分拍协议。
- 568 项活动权重的平衡树有 10 层加法，后续仍有 64×64 位量级乘法、宽加减和
  每周期 7 级恢复余数除法。它们仍可能成为 1.5625 ns 时序瓶颈。
- 16 拍×40 MS/s 要求 640 MHz；10 ns 综合周期仅对应 6.25 MS/s 的调度吞吐。
  RTL 仿真时钟设为 10 ns 不构成 640 MHz 的证据。
- 需以同一 source SHA、库、PVT、I/O delay、负载和 compile 模式复跑 DC。
  先 `check_design`，再分别查看树、乘法、除法路径，随后检查 transition、capacitance、
  fanout、未约束路径及综合后寄存器规模。脚本 WNS/TNS 摘要不能替代完整报告。
- `initial` 参数检查主要服务仿真；生产冻结参数同时受 DC 参数一致性流程约束。
  任意重新参数化都应单独复核数值范围与 elaboration，不能只靠仿真 guard。
- 真实异步模拟输出需要定义 CDC/握手，当前同步固定截止协议不覆盖亚稳态。
  当前端口未提供量化器模拟 dither 注入控制，因此数字模式回归不等于论文中
  SADC 注入和 RDAC 转移幅度的完整电路验证。

报告，不复用旧版面积/时序作为本次签核。下一次 EDA 环境可用时，应优先对上述路径
