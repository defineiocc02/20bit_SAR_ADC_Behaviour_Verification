# 失配预算：σ 到底取了多少，INL 为什么是这个数

> 回答两个问题："失配是多少"、"没有 LMS 校准怎么 INL 还这么好"。
> 结论先给：**σ = 0.1%（逐单元），INL 24.3 ppm —— 这个数不好，它是 σ=0.1% 的必然结果，
> 而且比论文差 11 倍。**0.31 ppm 那一行是零失配参考，不是结果。

数据：`data/mismatch_sweep.{json,csv}`；复现：`tools/run_mismatch_sweep.py`。

---

## 1. 用的失配是多少（精确值）

| 参数 | 值 | 说明 |
|:---|:---:|:---|
| `unit_mismatch_std` | **1×10⁻³（0.1%）** | 逐个 (slice, element) 独立正态，18 片 × (63+8) 个单元 |
| `bridge_mismatch_std` | 1×10⁻³ | 每片的桥接电容 |
| `feedback_mismatch_std` | **0** | 反馈电容理想（否则会混进增益误差） |
| 制造 seed | 20261105 | 同一 seed 下所有配置共用同一颗"芯片" |
| 单位电容 | 40.04 fF | 8 片合计 20.5 pF，与论文 kT/C 口径一致 |

这个 0.1% 是**工程假设，不是 PDK 数据**。40 nm MIM 在 40 fF 量级（面积约 20 µm²）的匹配
通常在 0.05%~0.2%，所以 0.1% 属于合理但不乐观的取值；不能用它去宣称某工艺的失配水平。

## 2. 扫描结果：INL 与 σ 严格成正比

256 点斜坡 × 8 次，端点拟合 INL：

| σ（相对） | σ (ppm) | 无 DEM (ppm FS) | 三维 DEM + 轮转选片 (ppm FS) | 逐码校准 (ppm FS) |
|:---:|---:|---:|---:|---:|
| 0 | 0 | 0.31 | 0.31 | — |
| 1×10⁻⁴ | 100 | 2.52 | 1.58 | **4.78** |
| 3×10⁻⁴ | 300 | 7.41 | 4.18 | 5.95 |
| **1×10⁻³** | **1000** | **24.29** | 13.94 | 12.40 |
| 3×10⁻³ | 3000 | 73.21 | 41.77 | 32.21 |

三条读数：

1. **斜率**：无 DEM **24 376 ppm / 单位 σ**；DEM（含轮转选片）**13 888**（0.57×）。
   σ 每涨 3 倍，INL 涨 2.94~3.01 倍——线性，不是巧合。
2. **论文 2.2 ppm 对应 σ_eff ≈ 9.0×10⁻⁵（0.009%）**，比我们的 0.1% 好 **11 倍**。
   也就是说：**在 σ=0.1% 下无论怎么调，都不可能得到 2.2 ppm**；论文那个数只能是
   "更好的器件 + 权值校正"共同的结果。
3. **校准有地板**：σ=1×10⁻⁴ 时校准后 4.78 ppm 反而**比不校准（2.52）更差**。
   表项噪声约 5 ppm，本源 INL 低于它时校准是在加噪声。所以校准不能无脑开。

> 校准列用的是扫描自己的评估网格（±0.985 FS、无偏移），与 [07](07_calibration.md) 里
> A5 的 10.46 ppm 差约 1 ppm 量级——评估网格不同（A5 偏移 0.37 个步长），不是矛盾。

## 3. 为什么 24 ppm 是"应该"的（手算对得上）

单片内、码 c 选中 m = c//8 个主单元（每个含 8 个 C_u）与 k = c%8 个子单元：

```
error(c) = (1/8) Σ_{slice s=1..8} [ 8·Σ_{i<m} ε_i,s + Σ_{j<k} ε'_j,s ]      （单位 1/512 FS）
Var      = (64m + k)·σ² / 8
```

中码 m=32、k=0 时 `Var = 256σ²`，std = 16σ = 16×10⁻³ = 0.016 个 1/512 FS = **31 ppm**；
去掉最佳拟合直线后（布朗桥去掉线性项）约乘 0.7 → **≈22 ppm**。
实测 24.3 ppm，比例系数 1.1。**模型没有隐藏的失配平均机制**——8 片并行本来就把单元误差
按 1/√8 摊掉，这已经算在 31 ppm 里了。

对照论文：2.2 ppm 需要 σ_eff ≈ 0.009%，与本模型假设差一个数量级。

## 4. "没有 LMS 校准怎么 INL 还这么好"——三个误会点

| 可能的误会 | 实际情况 |
|:---|:---|
| 把 0.31 ppm 当成结果 | 那是 **σ=0 的零失配参考**（A0 行），物理上不可达 |
| 把 24 ppm 当成"好" | 20 bit 下 1 LSB20 = 0.954 ppm，24 ppm = **25 LSB20**；论文是 2.3 LSB20 |
| 把 A5 的 11 ppm 当成"没校准" | A5 **做了校准**：8200 笔已知斜坡 → 512 项逐码表，最小二乘拟合。不是 LMS，但绝不是"没校准" |

LMS 在本仓库里也没有出现：任务树的 `EXPERIMENT_STANDARD` 用的是逐单元权值的 LMS 训练，
本仓库走的是"已知输入的最小二乘"，两者都属于"外部系数推导"，只是求解器不同。
本轮的 512 项表是**码域**最小二乘，不是逐单元 LMS——这也正是它压不到 2.2 ppm 的原因（见 07 §5）。

## 5. 测量口径的自我打折（这段必须看）

* 本表的 INL 是 **256 点斜坡 + 端点拟合**。20 bit 的严格 INL 需要码密度法（百万级样本/码）
  或至少 2²⁰ 点斜坡。点数少 ⇒ 拟合会吃掉一部分弯曲 ⇒ **数值偏乐观**。
* "分箱 DNL"是斜坡步长（约 256 LSB20）粒度上的微分非线性，**不是** 20 b DNL。
* 三次重复（`repeats=8`）只用来压均值噪声；`sigma_e` 单独列出，约 6~28 LSB20，
  随 σ 增大——那是逐笔随机选片把失配转成的噪声。

## 6. 不能声称

* 不能声称 0.1% 是这颗 ADC 的真实失配：它是假设值，没有 PDK 支撑。
* 不能声称"INL 24 ppm 已达标"：差论文 11 倍。
* 不能声称"校准总是有益"：σ ≤ 1e-4 时它会让 INL 变差（4.78 vs 2.52）。
* 不能声称扫描斜率可以外推到别的架构：斜率依赖 63+8 分段、8 片并行与 β=1/8。
