# d3d4_ip 接口合同（数字 IP 交付定义）

版本：v1.0（2026-11-15）
模块：`rtl/_legacy/tops/d3d4_ip.sv`
性质：**可综合、单时钟域、单拍输出的数字 IP**
证据：RTL 逐位对拍 / 门级等价 / 28nm 块级综合，见 `docs/ACCEPTANCE_STATUS.md`

---

## 一、这个 IP 做什么

给定 **RDAC 码 k** 与 **dither 字**，产生送给模拟侧的三组开关命令：

| 输出 | 含义 | 服务对象 |
|:---|:---|:---|
| `mask_o[159:0]` | 8 片 × 20 单元的主/子阵列开关 | **CONV 组**（转换期） |
| `pre_o[31:0]` | 8 片 × 4 位的采样预置开关 | **ACQ 组**（采样期） |
| `acq_ids_o` / `conv_ids_o` | 物理片号映射 | 片上路由 |

同时输出片组状态（`acq/conv/idle mask`）供片上调度使用。

**不做什么**（明确边界）：
- 不产生量化结果（`k` 由上游量化器给）
- 不含模拟电路、不含比较器、不含参考缓冲
- 不做失配校准（校准系数由外部 `w_tab` 提供，不在本 IP 内）

---

## 二、时钟与复位

| 项 | 约定 |
|:---|:---|
| 时钟域 | **单域** `clk`，无分频、无门控 |
| 复位 | `reset_n` 异步低有效，**同步释放**（外部保证） |
| 复位值 | 所有输出为 0；相位索引起点为 0 |
| 输出延迟 | **1 拍**（从握手沿到输出有效） |
| 吞吐 | 每拍可接收一笔（无内部反压） |

---

## 三、两种互斥模式

这是本 IP 最容易接错的地方，必须分清。

| 模式 | 使能 | 入口 | k 的来源 |
|:---|:---|:---|:---|
| **整码模式** | `ev_mode_i = 0` | `valid_i` / `ready_o` 握手 | `k_i[9:0]` 一次性给出 |
| **事件流模式** | `ev_mode_i = 1` | `ev_start_i` + `ev_bit_valid_i` × 9 | `follower_rt` 逐事件累加 |

### 模式互斥的硬保证

```systemverilog
assign ready_o = reset_n & ~ev_mode_i;
```

**事件流模式下 `ready_o` 恒为 0**，整码入口关闭。

> 为什么要这样：早期版本 `ready_o = reset_n` 恒为 1。事件流模式下若上游
> 按整码发一笔，IP 回"已接收"但该笔被静默丢弃（输出使能走的是
> `ev_bit_valid_i` 分支）—— **事务丢失且无错误标志**。

### `ev_mode_i` 的采样时机

`ev_mode_i` 决定 `out_en` 走哪条分支，是**当拍组合使用**，不锁存。
因此上游必须在整个事务期间保持模式稳定，不能在事务中途翻转。

## 四、整码模式时序

```
         ┌──┐  ┌──┐  ┌──┐
clk   ───┘  └──┘  └──┘  └──
              ▲
valid_i ──────┤1 ├──────────────
ready_o ──────┤1 ├──────────────
k_i     ──────╳ 采样
              │
mask_o  ──────┼────┤X├──────────   ← 握手沿后 1 拍有效
```

- `valid_i & ready_o` 同拍为高 → 该拍被接收
- 输出在**下一个上升沿**更新（1 拍延迟）
- `ready_o` 在整码模式下恒为 `reset_n`（无内部反压）

---

## 五、事件流模式时序（RDAC follower）

```
ev_start_i      ──┐  ┌──
                  └──┘     ← 冻结 upper，清前缀

ev_bit_valid_i  ─────┐1 ┌─┐1 ┌─ ... 9 次
ev_bit_i        ─────┤b0├─┤b1├─
ev_sar_index_i  ─────┤8 ├─┤7 ├─ ... 递减到 0

k_ev_o          ─────┤1 ├─┤3 ├─ ... 累积到 511
mask_o          ─────┤X ├─┤Y ├─ ... 每个事件都更新
ev_done_o       ──────────────────┐1 ┌──  ← 第 9 个事件后
```

**关键点**：每个有效事件都触发一次 `mask_o` 更新，这就是论文说的
"loaded as they develop"（边产生边载入）。

实测：k = 1 → 3 → 7 → 15 → 31 → 63 → 127 → 255 → 511，mask 同步变化 8/8 次。

## 六、合法性标志（必须检查）

| 端口 | 含义 | 何时为 1 |
|:---|:---|:---|
| `k_range_err_o` | k 超出合同表达范围 | `k_use > 520` |
| `ev_err_o` | follower 前缀 < upper（会下溢） | 该事件置位 |
| `ev_proto_err_o` | 位序/重复/缺位/qid 协议违例 | 事务级粘滞 |

### `k_range_err_o` 的合同依据

合同原文（`docs/ISSCC2024_ONCHIP_CONTRACT_v2.md:130`）：

> 超过合同表达范围必须报错，**不做模 512 回绕或静默夹紧**。

实测（穷举）：`k=0..520` 无报错，`k=521..1023` **全部报错**。

> 补这个端口前，k=521/600/1023 都会静默返回"全 1" mask，
> 与合法的 k=520 完全无法区分。

### 越界时 `mask_o` 的内容不作约定

合同只要求"报错"，没规定越界时 mask 该是什么值。
**下游不得在 `k_range_err_o=1` 时使用 `mask_o`。**

## 七、位序约定（接错的常见原因）

输出全部是打包向量，位序在 RTL 源码里只有一处定义：

| 端口 | 位序 | 说明 |
|:---|:---|:---|
| `mask_o` | `bit = 20*s + j` | s=片 0..7，j=单元 0..19 |
| `pre_o` | `bit = 4*s + b` | s=片 0..7，b=开关位 0..3 |
| `acq_ids_o` | `bit = 5*n +: 5` | n=0..7，**按片号升序** |

`pre_o` 的 4 位内部顺序是 `[b2, b1, b0, bal]`（**MSB-first**），
即 `bit3=b2(4Cu)`、`bit2=b1(2Cu)`、`bit1=b0(1Cu)`、`bit0=bal`。

> 这两处都踩过坑：
> 1. 非打包数组端口被 DC 展平时**顺序与源码下标相反**，
>    门级仿真整片错位（实测 110,080 组失配）。
> 2. `pre_o` 位序颠倒过一次，症状是 `got=aaaaa888 want=55555111`。

## 八、k 的范围语义

| k 范围 | 含义 | 是否合法 |
|:---|:---|:---|
| 0..511 | 普通区，`k = 64H + 8V + L` | ✅ |
| 512..519 | guard：主阵列全选 + 子阵列 0..7 | ✅ |
| 520 | guard：子阵列 4+2+1+1 全选 | ✅ |
| 521..1023 | 越界 | ❌ `k_range_err_o=1` |

**事件流模式下 k 只有 0..511**（`follower_rt` 的 `k_ev_o` 是 9 位），
guard 不可达。这是已知缺口，不是 bug —— 扩展 follower 位宽会破坏
已通过的 6246 事件回归。

---

## 九、两相位交织的分工（必读）

`sched18` 把 18 片分成 ACQ(8) / CONV(8) / IDLE(2)。同一拍里：

- **`mask_o` 服务于 CONV 组** —— 转换期才需要 RDAC 开关
- **`pre_o` 服务于 ACQ 组** —— 采样期才需要 dither 预置

下游必须用 `conv_ids_o` 把 `mask_o` 的 8 个 slot 映射到物理片，
用 `acq_ids_o` 把 `pre_o` 映射到采集片。**不要用同一套 ID 映射两者。**

## 十、综合实现参考（TSMC 28HPC+ SS）

| 项 | 值 |
|:---|:---|
| 面积 | 1770.08 µm²（3017 cells，322 FF） |
| 逻辑级数 | 40 |
| 关键路径 | 2.82 ns |
| setup @25ns | +19.88 ns |
| hold @25ns | +0.00095 ns（**不构成签核**，见 SYNTH_D3D4.md §4） |
| 真实能力 | **2.788 ns（自然实现，100 ns 宽松约束实测）** → 约 359 MHz |

为什么说 2.82 ns 是真实值而不是优化堆出来的：另跑一组 100 ns 宽松约束，
综合器不做时序驱动的重优化，得到的自然实现是 **2.788 ns**，
与 25 ns 约束下的 2.82 ns 几乎相同。二者之差 0.03 ns 属于布局/单元选择抖动。

相对 40 MS/s（25 ns）有约 **9 倍**余量。

## 十一、不能声称的

| 项 | 原因 |
|:---|:---|
| hold 收敛 | ZeroWireload，无时钟树；0.00095 ns 不是签核数字 |
| 功耗 | 无色切换率输入 |
| INL/DNL/DR/噪声 | 数字端不可验证，需模拟闭环 |
| 与 ADI 硅片逐位一致 | 随机序列/相位表原文未披露 |
| EM/IR、P&R、DRC/LVS | 未做 |

**CLAIM = IMPLEMENTATION_ONLY + BLOCK_LEVEL_SYNTH。**
