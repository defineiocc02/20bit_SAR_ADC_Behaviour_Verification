## 2. 优先级最高的综合风险

### R1：存储结构和并行读取，而非简单的数组语法问题

`weight_store` 向外暴露 `18×71×48 = 61,344 bit` 全阵列；`recon_core` 按 8 个 `slice_id` 各选择 71 项，即运行时选择 `8×71×48 = 27,264 bit`。阵列具有同步复位、随机单点写入和大规模并行读取，不能期待换成 unpacked 数组就自动获得普通 1R1W SRAM。

独立综合 `recon_core` 时，slice_id 是通用输入，对应较宽的选择网络。完整顶层目前只使用固定 ping-pong 两组：0–7 与 8–15；如果综合器能跨层传播约束，每个位置可能简化为两组间选择。因此必须分别报告 standalone recon 与 integrated top 的结果，不能把两者面积直接等同。16/17 是预留 slice，不能单凭本模式没有选中就认定多余。

建议先分物理 slice 建 bank，明确每周期实际读端口和重构时序，再决定寄存器、SRAM 或局部权重预聚合。每个 bank 的名义总和、dither mask 权重和可在配置阶段更新并缓存；不能先换 RAM 再期待原有 568 项并行读接口保持不变。

### R2：重构前端同拍归约太多

`recon_core` 的组合块同时形成 `psW/psWa/psWon/psWr`，每组循环 71 项，再合并 8 组。综合器可能重排算术，不能直接把源码顺序加法等同于布局后的 71 级串行链。但目前没有明确流水边界，这些选择、掩码和归约都进入同一阶段。

建议按顺序推进：

1. 将与样本无关的每物理 slice 总和和 mask 和前移到配置期；提交成功后原子启用缓存。
2. 对真正随样本变化的 switched-weight sum 显式分组，构建平衡树。71 项树约 7 层，8 组再约 3 层只是算术结构估计，不是实际门级延迟。
3. 根据综合关键路径设置寄存器边界，同时流水传递 bank、ADC2、inj、offset、mask、错误标志与样本有效位；用逐样本 scoreboard 防止“数值对了但样本错位”。

当前 `gain` 取决于所选物理组与 sampling mask enable；`main_on` 影响 rails，不直接改变 gain。固定两组调度可研究最多“2 组 × 2 mask 状态”的 gain 缓存。推广到更一般的 slice 轮换后，该缓存键也必须变化。

### R3：宽乘加和除法器限制 640 MHz 的可行性

阶段 B 含 130 位结果容器的 `total_s × inj_r`、132 位算术和 96 位范围检查。有效操作数是 64 位无符号总量和 64 位有符号输入；不能从表达式扩展写法直接宣称一定综合成 130×130 乘法器，应检查算术单元报告和实际网表。

当前合法权重 `<2^47`，选中 568 项的总和 `<2^57`；完整 1278 项总和 `<2^58`。可据此研究位宽缩减，但必须覆盖极限合法配置及全部外部输入，不能用典型 `1<<26` 权重或某个测试中 inj=0 代替证明。范围检查、负数符号扩展和 floor 舍入语义需要逐位保持。

`div_floor` 每周期串行执行 7 次 restoring 比较/减法，余数数据通路为 65 位；`mag[bitpos]` 还含计数驱动的位选择。P_STAGES 表示每周期展开级数，不是流水段数。减少展开会降低单周期逻辑，但增加延迟：当前 P7 对应 9 次迭代、重构口径 11 拍；P4 对应 16 次迭代、18 拍，已超出 16 相位节拍。不能只改参数就宣称问题解决。

首先可比较固定分块移位与动态位选择的实现；其后再比较分段流水除法、并行通道或经证明带修正的倒数乘法。除法器不是每拍都能接收 start，必须分别预算 latency 与 initiation interval，不能只看最后一个输出用了几拍。

### R4：接口相位成立不等于 ready 握手成立

顶层的 `sadc_rdy/adc2_rdy` 没有参与控制，`sadc_latch/adc2_latch` 也没有用于采样输入锁存；重构使用接入的当前数据。因此集成必须明确外部模块何时更新、保持到哪一拍，以及所有数据是否同一时钟域。理想测试台按相位送数，不能证明迟到输入或 CDC 安全。

下一步应明确固定相位契约还是有 backpressure 的握手契约。固定相位方案应在约定 latch 拍采样并检测迟到/缺失；握手方案需要同时修改 FSM、吞吐量承诺和 scoreboard。不能只给 ready 加同步器而不处理多位数据的一致性。

### R5：高扇出与实现约束

61,344 个权重状态位加完整性 bitmap，带来复位、写译码及读选择的负载。源码是同步复位，不能按“异步复位恢复/撤销”问题套用。可以研究取消数据复位、仅用有效位控制初始化，但会改变复位后读回及 X 行为，需新契约和四态回归后再实施。

## 3. 综合报告还不能作为签核结论的原因

修复后的 `OK` 仍只依据所查询的 max slack 是否非负；hold、max transition、check_design 等虽然生成报告，并未全部纳入自动验收。存在一个时序路径不等于不存在未约束路径。下一轮门禁应分别覆盖 setup/hold、未约束端点、锁存器、组合环、设计规则及黑盒，不应用大范围 false path 隐藏真实失败。

已将旧 `LOAD_PF × 1000` 改为 `LOAD_PF / LIB_CAP_UNIT_PF`，默认 1.0 对应仓库记录的 pF 库；重跑时必须核对实际库单位，其他单位通过环境变量显式提供。输入/输出 delay 应制定 min/max 两类真实预算，区分配置接口与数据接口的使用方式。当前没有加载切换活动的 `report_power` 只能称默认活动估算，不能用于论文功耗或 FoM 复现结论。

每次综合归档应包括完整 RTL/脚本摘要、参数、工具版本、库标识与角、实际 compile 命令、约束、报告、网表和退出状态。旧报告的 `ultra` 标签与旧 TNS 字段需要重新核对，不能直接用于优化前后比较。

## 4. 可执行的分阶段验收

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| A：数字基线 | 本分支全部 RTL 回归、合法/非法配置、算术边界、复位清除、完整 trace | 所有预期检查完成，0 mismatch；超时或工具错误均失败 |
| B：可信综合基线 | 相同 RTL、库、约束分别综合 weight_store / div_floor / recon_core / 顶层；先用 10 ns 定位结构 | 保存真实报告；区分通用独立接口与顶层常量传播；约束完整性独立验收 |
| C：结构优化 | 配置期聚合、归约树/流水、bank 读取规划；每次一个独立改动 | 同一向量逐位等价；错误与 valid 对齐；面积及关键路径有实际前后证据 |
| D：40 MS/s | 16 相位要求 640 MHz，即 1.5625 ns；结合可实现频率重新选时分/并行架构 | 目标节拍、II 和 latency 同时满足；在指定 PVT 下完成 STA，之后以布线后结果验收 |

10 ns 时钟、16 相位仅对应 6.25 MS/s，不能报告为 40 MS/s。若 1.5625 ns 不可达，应先修改架构或吞吐量目标，再调整约束；不要放宽时钟后保留原性能标签。
