# 关键缺陷：`initial` 初始化的 LUT 在综合中被丢弃

时间：2026-11-16　基线：`45e54f1`
影响：`recip_q60` 的 Newton 初值表 → `I = RND(2^60,G)` → 20 位输出

## 1. 缺陷本身

`rtl/recip_q60.sv` 用 `initial` 块初始化 64 项种子表：

```systemverilog
logic [30:0] lut [0:63];
initial begin
    lut[ 0] = 31'd1065418243;  lut[ 1] = 31'd1049152316;
    ... // 共 64 项
end
assign u0 = lut[idx];
```

**DC 的语义里 `initial` 块被忽略**，日志原文：

```
Warning: /tmp/ip/rtl/recip_q60.sv:82: The statements in initial blocks are ignored. (VER-281)
```

## 2. 后果链

```
VER-281   initial 被忽略
   ↓
lut 全 X / 常值 -> u0 是常量
   ↓
u0_r_reg[30:0] 被 OPT-1206 删除（"is a constant and will be removed"）
   ↓
Newton 迭代退化：u1 = u0 + u0·e，u0=常量时 u1 也是常量
   ↓
inv_q60 不再是 G 的函数
```

网表里可直接看到退化结果：

```verilog
assign inv_q60[0] = \inv_q60[26] ;
assign inv_q60[1] = \inv_q60[26] ;
assign inv_q60[2] = \inv_q60[26] ;
```

多个 bit 接到同一根网，说明它们已经是同一个常数。

DC 日志里 `OPT-1206` 去重后**只有三个寄存器**被当常量删除：

```
u0_r_reg          ← LUT 输出寄存器
i2_q_reg          ← 依赖 inv 的 recon 中间量
quiet_cnt_q_reg   ← 依赖…（见 §4）
```

## 3. 三条独立证据

| 证据 | 内容 |
|:---|:---|
| **Formality** | 20 failing：`i_q60_reg` 19 个 bit + `Wm_q30_reg[39]`。**散布式失败**（27 bit 中 19 错 8 对），符合"退化成常数后部分 bit 恰好正确" |
| **门级等价** | 58 处差异**全部在 `out_code`**：RTL 给 `0xFFF00`（A 笔正确），网表给 `0x80000`（错用了 B 的值） |
| **网表结构** | `inv_q60[0..2]` 同接 `inv_q60[26]` + `VER-281` 警告 |

三条互相印证，不是猜测。

## 4. 为什么此前多轮验证没抓到

| 验证 | 为什么漏 |
|:---|:---|
| `tb_recip_q60`（43766 笔） | RTL 级仿真，`initial` 在仿真里**是有效的**，所以全过 |
| `tb_recip_rnd`（20817 笔） | 同上 |
| 旧门级烟测（61 观察沿） | 观察沿太少、且 raw 由节点模型给固定值，recon 输出恰好落在那 8 个"对的 bit"覆盖的范围内 |
| `tb_i4b_e2e`（25 项） | RTL 级，`initial` 有效 |
| **Formality** | **抓到了**：20 failing |
| **新门级 e2e（两笔完整事务）** | **抓到了**：58 处 `out_code` 差异 |

**教训：仿真通过 ≠ 可综合。** `initial` 初始化 ROM 在仿真里完美工作，
在综合里被直接丢弃，只有形式化等价或**足够长的**门级仿真才能发现。

## 4b. 独立仿真铁证（12 个合法 G 逐一扫描）

把网表的 `recip_rnd_v21` + `recip_q60` 单独抽出（829 行），用**完全相同的
testbench**（单脉冲、negedge 驱动、逐 G 等 `valid_o`）分别跑 RTL 与网表：

| G | 精确 RND | RTL | 网表 |
|---|--:|--:|--:|
| 17179869184 (2^34 下界) | 67108864 | 67108864 | **2** |
| 20000000000 | 57646075 | 57646075 | **2** |
| 25000000000 | 46116860 | 46116860 | **2** |
| 30000000000 | 38430717 | 38430717 | **2** |
| 34359738368 (2^35) | 33554432 | 33554432 | **2** |
| 40000000000 | 28823038 | 28823038 | **2** |
| 45000000000 | 25620478 | 25620478 | **2** |
| 51539607552 (2^36 上界) | 22369621 | 22369621 | **2** |
| 55000000000 | 20962209 | 20962209 | **2** |
| 60000000000 | 19215358 | 19215358 | **2** |
| 65000000000 | 17737254 | 17737254 | **2** |
| 68719476736 (2^36) | 16777216 | 16777216 | **2** |

**RTL 与精确 RND：12/12 全对。网表：12/12 全部输出常数 2。**

### 为什么是常数 2

网表里 `recip_rnd_v21` 的 27 个 `i_q60_reg` 的 D 端：26 个接 `n2`、
1 个（bit[26]）接 `N70`，而：

```verilog
TIELBWP7T40P140 U3 ( .ZN(n2) );   // 恒 0
TIEHBWP7T40P140 U4 ( .Z(n1) );    // 恒 1
```

所以 `i_q60 = {0...0, 1, 0} = 2`。

同一 testbench 的逐拍 trace 也确认：网表 `cyc=8 v_o=1 i_q60=2`，
RTL `cyc=8 v_o=1 i_q60=33554432`，**其余 12 拍完全一致** ——
说明只有数据通路坏了，`valid` / `err` / 时序全对。

## 4c. SVF 自己记录了这件事

DC 通过 SVF 明确告诉 Formality "u0_r_reg 恒 0"：

```
/tmp/formality2_svf/svf.txt:11750+
guide_reg_constant -design {recip_q60} {u0_r_reg[N]} {0}   ← 31 条
```

**所以这不是 Formality 的锅 —— 是网表本身错了，SVF 如实记录了 DC 的错误推断。**

## 4d. 关于 `Wm_q30_reg` 的失败：不是同一根因

`Wm_q30` 的 failing 集合**随网表版本漂移**：

| 网表轮次 | failing 点 |
|:---|:---|
| 09:15 那轮 | `Wm_q30_reg[39]` + `i_q60_reg` 19 bit |
| 10:17 那轮 | `Wm_q30_reg[0..5]`（6 个）+ `i_q60_reg` 14 bit |

**失败集合不稳定 = "锥里有 X/未初始化"的典型特征**，不是稳定逻辑差异。

已知事实：
- `wsum_v21` 的 `f_Wm`/`f_Wp`/`f_G` 用的是**端口**进来的权重表，
  不是 `initial`，所以没有"LUT 被丢"问题
- `wsum_v21` 里 1 个 TIE 单元驱动 `G_q30[49..63]`（15 bit），
  而这 15 bit 本就被 `OPT-1206` 当常量删了，SVF 有对应 `guide_reg_constant`

**正确表述**：`G_q30` 高位常量折叠 + 整条数通路的 X 污染。
需在 `f_lut` 修好后重跑，看是否连带消失。**若仍有残留，那才是新的真问题。**

## 5. 修法

把 `initial` 块改成可综合的 `case` 语句函数：

```systemverilog
function automatic logic [30:0] f_lut(input logic [5:0] i);
    case (i)
        6'd0 : f_lut = 31'd1065418243;
        ...
        6'd63: f_lut = 31'd538976288;
        default: f_lut = 31'd0;
    endcase
endfunction
assign u0 = f_lut(idx);
```

- 数值与原来逐字一致（脚本从原 `initial` 块提取，不是手抄）
- 可综合、可形式等价（`case` 是纯组合逻辑，无初始化语义）
- 功能不变：`tb_recip_q60` **43766 笔仍逐位一致**

## 6. 修后待验证

1. 重新综合后 `VER-281` 应为 **0**、`OPT-1206` 应显著减少、
   `u0_r_reg` 应**存在**于网表
2. 门级 e2e 应从 58 处差异降到 **0**，且 `out_code` 恢复 `0xFFF00` / `0x80000`
3. Formality 从 20 failing 应降到 0（需重跑，约 15 min）
