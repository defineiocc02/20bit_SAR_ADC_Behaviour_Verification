## 1. FIG.17 直接给出的计数（本次新判读）

FIG.17 上半是**同一张图的两块**，用点划线分成 `Main DAC` 与 `Sub DAC`：

| 位 | 图上画的 | 计数标签 |
|:---|:---|:---|
| B0–B3 | `01011...0` 经 shuffler 320 → `10101...0` → 直接送 8 个 DAC 行 | 每片行内 `10101...0`（312）|
| B4 | 常量 `1`，**不经过 any shuffler** | `2x` |
| B5、B6 | 常量 `1`、`0`，来自点划线右侧 `Sub DAC` 区域 | `8x`、`4x` |
| **竖排三列（314）** | 每片 3 位 | 自上而下 `001 / 101 / 100 / 010 / 010 / 010 / 010 / 110` |

中间 shuffler 322 接收 **B3（直通）、B4、B5**，其输出再分 `8x / 4x / 4x` 三路。

**结论（可核对）**：

1. B4 是**主阵列侧的单一权重步**，标签 `2x`，**没有被展开成跨片一元组**；
   若 B4 是"8 片里选 8 个"的一元组，权重应为 8x 且必须写一个 8 长的排列——
   图上既没有 8 个格子，标签也不是 8x。
2. 竖排第三列（随片变化：0,1,0,0,0,0,0,0）**没有权重标签**，最右竖边像括号一样收口。
   本文只记"图上未标"，**不赋予任何含义**。
   （上一轮曾误把这一列读成"第三位"，同一误读也导致过 528 单元的反证；见 §2.1。）
3. B5/B6 进入 shuffler 322，说明**子阵列的二进制位也要参与跨片配对**。

## 2.1 计数的两种口径（这是本轮最实质的一次判读修正）

初读时把 FIG.17 的 `2x / 4x / 8x` 当成"每片多少列"，于是推出"528 个单元 > 512 个码"
的反证。**这个反证后来被 FIG.20 推翻了**：

| 图 | 文字 | 读作 |
|:---|:---|:---|
| FIG.20 | 顶部 MUX 簇 350 的三个输入分别标 **B5=4x、B6=2x、B7=2x** | 一个"共享权重 + 按片分配"的 MUX，权重从 1x 起以 2 的幂增长 |
| FIG.19 | 顶层行 `8C(B5) / 4C(B6) / 2C(B7) / C(B8)`，UNARY ENCODER 306 输入 `8x / 4x / 2x` | 8C 那一片要消耗 **8** 份"每片 1x 的单元" |
| FIG.11 | 每片都有 8C/4C/2C/1C/C 五列 | 子阵列权重是**每片**的电容值 |

**唯一自洽的读法**：`Nx` 是"这个权重用的是全部 8 片里每片 1C 当量的总倍数"，
子阵列每一位在 8 片上各有一份。于是：

* 子阵列每位权重（全 8 片合计）= 8 × {8, 4, 2, 1} = **64 / 32 / 16 / 8 个 1C 当量**；
* 主阵列每位权重（全 8 片合计）= 8 × 2 = **16 个 1C 当量**；
* 满量程 = 16×31 + 64+32+16+8 + **每片 1C 终接 ×8 = 8** = 616 个 1C 当量；
* **616 / 512 不是 2 的幂，也不是整数** ⇒ 单位步长**不相等**。

**结论**：9 位码在 17/5 阵列上不是"线性均匀"码本，而是带权重的分段码本；
"512 个码 → 512 个等距电平"这个前提在**原件层面**就不成立。
因此本仓库**不**以"码本等距/单调"作验收，改为按原件权重直接求**权重量化电平表**
（见 `docs/mechanisms/` 与 `topology/mapper.py`），并保留"每码电平必须逐码可枚举"这条可核对性质。

## 2.2 位权实测：B0–B3 的排列把位权打乱了（可复算）

把 `dem3d.fig11_masks` 在 B4 单步化以后逐位求"打开这一位增加多少 1C 当量"（全 8 片合计）：

| 码位 | 值 | 增量（1C 当量） |
|:---|:--:|:--:|
| B0 / B1 / B2 / B3 | 1/2/4/8 | 8 / 16 / 24 / 32（每步 +8，共覆盖 128）|
| B4 | 16 | 8 |
| B5 | 32 | 64 |
| B6 | 64 | 32 |
| B7 | 128 | 16 |
| B8 | 256 | 8 |

显然 `B0` 的步进（8）与 `B4`（8）、`B8`（8）**相等**，`B5` 反而比 `B1` 小。
这不是实现错误，而是"B0–B3 经 320 排列到 15 个 2C"这一层在图上**没有给出公式**的直接后果：
没有正文，就无法确定哪位对应哪些 2C，位权当然无法排列成 2 的幂。

**因此本条明确标"待正文核对"**，并给出可核对的替代判据（不依赖位权）：

* 每码掩码的**单位数守恒**：`Σ 选通电容权重(实际) == 由码定义的权重(名义)`，
  对 512 个码 × 8 片逐片成立（现有 `nominal_conservation`/`usage_uniformity` 已覆盖）；
* 每码掩码的**片间对称性**：同码下 8 片选通权重相等（原图是"shared weight"，必须相等）。

**不做**的事：不为了让"单调"成立而重排码位——那等于编造正文。

### 6.2 仍未闭合、且**本轮不臆造**的一条

**"每片相位不同"与"逐码权重"互相冲突。**

* 实测：同样的码在 8 片按 `(h+pid)%15` 取不同列，得到的等效权重不同（端点比 0.99795，
  DNL 仍为 0）；
* 若要求端到端与逐码权重都逐位一致，则 8 片的信号连接必须**同相**
  （仓库早已记录：`ASSUMED a=1 且所有切片相同`）；
* 那么"错配抵消"只能靠**片间物理顺序**或**权重分配**实现，即 FIG.16 的 320/322
  把"哪些电容归哪片"打散——但图上**没有给排列公式**，正文段落本轮未定位。

**处置**：上述两种情形都保留为**可选项**，默认取"同相 a"，并把
"错配抵消的替代实现"列为 P1 缺口；不以任何一侧冒充原件结论。

### 6.3 下一轮的第一件事

`dither` 在 17/5 上失效（`ra_sat` 全 True、静态均值误差不降），根因是
`c_lsb = nominal_c_norm/512` 的 `nominal_c_norm` 用了**8 片并联**口径，
而码本律按**每片**口径定义 LSB = β·C_u。先把两者统一到同一个公式，
再重跑 dither/校准；在统一之前，任何 dither 结论都不成立。

### 7.3 仍未闭合（本轮新增的唯一阻塞，且**先于本轮存在**）

零输入时 `ra_sat` 8/8 饱和。用 `git stash` 在 `1ef9348` 上实测：
**基线同样是 8/8**，所以不是本轮引入；本轮把 `vd` 从 −0.323/−0.074 改善到 −0.091/−0.102，
但仍未对齐码本 ±0.0059。

已排除的嫌疑（逐条实测）：掩码选中集合、器件电容、β、名义解码权重、RA 增益

**剩余嫌疑**：`charge_from_masks` 返回的是**单端**节点电荷

两者在码 0/511 近似相等、中间码偏 0.1 V，正是"未选单元数随码变化"的指纹。
下一步应统一到差分口径（`x_eq = v_fs·(2·drive/c_slice − 1)`），而不是逐层打补丁。

## 8. 2026-11-13 最终定位：主链已恢复（ra_sat 8/8 → 0/8）

### 8.1 真正的根因：9 位码的位分配在三处各写各的

`defaults`（码本律）、`dem3d.fig11_masks`（掩码律）、`charge_from_masks`（电荷律）
对"码 → 选中哪些单元"给出三个不同答案，于是：

* 码本端点落在 2.818 V（不是 3.0）；
* 电荷被换算成 −0.088 V，码本却是 +0.0059 V；
* 残差 0.086 V × G=31 = 2.7 V ≫ RA 限幅 0.5 V → 零输入就全饱和。

### 8.2 统一后的唯一分解（三处同一套，缺一即回退）

```
位分配    : B0..B4 主段 5 位主码 P=0..31；B5..B8 子阵列 8/4/2/1 × β
主段分解  : therm = min(P//2, 15) 个 2C，余下 (P-2*therm) 用 B4/S4 两个 1C 补
分母      : cn = 31 + β·15 C（15×2C + B4 的 1C）
端点闭合  : drive(511) = 31.9375 = cn  ⇒  v(511) = +v_fs 精确成立
采样态电容: S4（第 17 列）与子阵列哑位**不进转换驱动、不进分母**
```

### 8.3 实测（seed 20261105，零输入）

| 判据 | 结果 |
|:---|:---|
| 码本端点 | −3.00000 … +3.00000 V |
| 码本单调 | 严格递增，零交点恰在码 256 |
| 电荷 vs 码本 | 码 0/255/256/511 差 ≤ 0.0002 V（失配范围内）|
| 零输入 `ra_sat` | **8/8 → 0/8** |

### 8.4 仍未闭合：dither 幅度（不是码本问题）

* RA 输入端允许的残差 = `ra_v_clip/G` = 0.5/31 ≈ **1.38 LSB9**；
* 现 dither 程序的 6 位字最大幅度 = **8 LSB9**（0.0938 V），超 5.8 倍；
* 论文写 "dither range enhanced by 2b from quantizer to RDAC"，
  说明**量化器侧** dither 才是 1~2 LSB 量级，RDAC 侧被放大 4 倍；
  模型把 RDAC 侧幅度直接当残差摆幅，尺度错；
* dither 专利 `[10]` 全 36 页**无文本层**（实测 0 字符），无法核对正文的幅度定义。

**处置**：标"dither 幅度待确认"，不为了提高测试通过率而放宽 `ra_v_clip` 或
`adc2` 窗口——那两个参数与 ADC2 窗口（0.45 V ≈ ±0.5 LSB9×G）是自洽的。
