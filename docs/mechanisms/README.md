## 六段模板（写新专题时照抄）

```markdown
# <技术名>：<专利号> Fig.<n> → 当前实现

## ① 专利原图
| 项 | 内容 | 状态 |
（专利号、图号、对应段落、相关论文页；原件不在库内就写"待核对"，不得凭印象补器件编号）

## ② 原理与事件过程
（沿原图逐事件：采样 / 判决 / 码更新 / 参考切换 / 余差；标明信号、电荷、控制各往哪走）

## ③ 当前实现映射
| 专利原图 | 当前模型对象 | 函数 | 关键变量 | 主链调用位置 |
（每行必须能在仓库里点到文件；不存在的写"未实现"）

## ④ 一个真实样本
（样本号、输入、关键中间量、最终码与误差；组合出来的样本必须标"哪些是记录的、哪些是重算的"）

## ⑤ 同条件开/关
（只改被测技术，其他固定；给内部量与最终指标；代价必须同列）

## ⑥ 差距与下一步
（差异是否影响结论 + 下一项改哪个模块）
```

## 对齐状态定义（全库统一）

| 状态 | 含义 | 允许的声称 |
|:---:|:---|:---|
| 已实现 | 有代码、有门禁测试、在主链可观测 | 可以声称"实现了该机制" |
| 等效 | 保留原图的因果位置，但换了实现（如电荷口代替电容网络） | 只能声称"等效端口"，不能声称复现了原图电路 |
| 部分 | 有明确缺口（缺保留列、缺 AUX、缺数字输出） | 只能声称已实现的部分 |
| 未实现 | 没有代码或没有接入主链 | 不得出现在性能结论里 |

## 三条写作纪律

1. **图号先行**：没有图号的技术说明，一律视为"工程选择"，不得标成"复现"。
2. **数字同源**：文中每个数必须能在 `docs/reviews/20261113_p3p4/data/*.json` 或
   `figures/figures.json` 里找到；找不到就不写。
3. **缺口同页**：差距不能放到别的文档里——和结论放在同一页，读者才不会只看到好消息。
