# 除法改倒数乘：一次失败尝试的记录

## 做了什么

把 `recon_d5` 的两处整数除法换成倒数乘，常数在**全输入范围**上用 Python 穷举验证过
逐位等价：

| 除法 | 替代 | 验证 |
|:---|:---|:---|
| `((2a+1)*144+2)/5` | `(x*838861 + 2^21) >> 22` | 0..1,179,506 全枚举一致 |
| `round(x/96)` | `(|x|*44739243 + 2^31) >> 32` | ±5.4e7 步进抽样一致 |

功能验证：`recon_d5` 1987 组、`digital_top` 600 组 **均 0 失配**。功能上是成功的。

## 结果：综合反而变差

| 指标 | 除法版 | 倒数乘版 | 变化 |
|:---|---:|---:|:---|
| 面积 | 38546 µm² | **78190 µm²** | **+103%** |
| 关键路径 | 62.72 ns | 63.15 ns | +0.7% |

## 为什么

我把中间量加宽到了 **64 位**（`logic signed [63:0]`）来容纳乘积，
SMIC180 的 64×64 乘法器面积远超它替掉的除法器。

正确的做法是**把宽度收窄**：`(2a+1)*144+2` 最大约 2^21，乘 838861（2^20）需要
**42 位**；`x` 最大 2^26，乘 44739243（2^26）需要 **52 位**。用 42/52 位而不是 64 位，
面积才能降下来。

## 结论

**已回退到除法版。** 这不是"优化没达标"，是"优化方式选错了"——
倒数乘本身没错，错在没算清位宽就套了 64 位。

下一步要么按 42/52 位重做，要么先做流水（把 `adc2 → code` 拆成两级寄存器），
后者对 62.72 ns → 25 ns 的收益更直接。
