### R2 · P1：32位截断的证明前提未成为配置验收条件

**[源码确认]** 新写口接受任意40位数据，只检查地址；`recon_v21.sv:104–109` 检查 G 非零、alpha 范围和 epoch，不检查全宽 G 的上下限或子权重上限。`:305` 先截 G 的低44位再给倒数；`:385` 直接将宽 X 的低32位解释为有符号数。

**[独立整数反例，非本轮 RTL 仿真]** 选择八个合法且互异的片号，每个主权重取 `2^27`，得到 `G=2^34`；只把一个选中的子权重写为 `2^39`，故 `Wm=2^39,Wp=0`。取 `raw=2048,b=768,alpha=2^30`、同一 epoch，则：

```text
Y-b = 0
I = 2^26
X = 3,170,893,824
正确宽算术末级饱和码 = 0xFFFFF
低32位重新解释为有符号数 = -1,124,073,472
按当前截断路径得到码 = 0x00000
```

这些数据可装入当前写口，并不会触发现有保护条件；子权重违反作者额外提出的 A5，但 A5 尚未成为现行合同/配置检查。这不是否定名义权重下的算法，而是证明“代码已保证所有范围前提”的说法不成立。

另一个独立入口缺口是 `G=2^44+2^34`：可由128个 `2^37+2^27` 主权重构造，均在40位容器内。截为44位后别名成合法的 `2^34`，倒数侧范围检查不能代表原始64位 G 已通过检查。

**最小处置方向：** 将实际采用的算术 profile 纳入配置合同并验收全表，或保持足够位宽处理更大范围。不能仅给证明脚本加假设而继续接受不符合假设的配置。当前顶层固定 alpha=1，不能把单元支持的可变 alpha 当成已接入的顶层模式。

可独立复算：

```sh
python3 - <<'PY'
G, Wm = 1 << 34, 1 << 39
N = 6*Wm - 3*G
X = (N*((1 << 60)//G)) // (1 << 36)
x32 = (X + (1 << 31)) % (1 << 32) - (1 << 31)
def rnd(n, d):
    q, r = divmod(abs(n), d)
    return (-1 if n < 0 else 1) * (q + (2*r >= d))
def code(x):
    return min((1 << 20)-1, max(0, rnd(x, 96) + (1 << 19)))
print(X, x32, hex(code(X)), hex(code(x32)))
PY
```

### R3 · P2：倒数数据与valid错一拍，当前数值正确依赖隐含实现条件

**[源码及逐沿整数复核]** `recon_v21.sv:305` 将 `v1_q` 与较早的 `G1a_q` 一起送给倒数单元。倒数各级在 invalid 拍也无条件更新数据；S2c在 `:341–345` 固定取数，不使用 `ri_valid`。因此 A 的数据可以提前到达并被正确消费，但其 valid 标记晚一拍。

### 3.1 X位宽论证怎样修正

`prove_xwidth.py:60–65` 将 `Wm`、`Wp` 都界为32个子权重的和；`Wm`还含选中的主权重，因此这一步不成立。不能因为脚本打印PROVEN就忽略它。

令 `S` 为八片全部子权重之和，主选中和 `M∈[0,G]`，子post和 `P∈[0,S]`，pre和 `Wp∈[0,S]`。则：

```text
Wm = M + P
|6Wm − 3G − 6Wp| <= 3G + 6S
S <= 8×4×4×2^30                 （仍依赖A5）
```

沿用脚本保守的 `|Z|<=153090561`、`G<=64×2^30`、`I<=67108865`，用向上取整处理负数floor的绝对值，可得：

```text
|N| <= 1,040,589,946,944
|X| <= ceil(|N|max × Imax / 2^36)
     <= 1,016,201,136 < 2^31
```

这说明当前32位思路在这些前提下可以保留，不要求无依据地退回大位宽；需要修正证明步骤并落实范围前提。`b_q24`实际为signed27，可表示 `[-2^26,2^26−1]`，文中对称界用作保守上界，不能把正端 `+2^26` 当可直接装入的值。

本文按委托明确给出的alpha范围 `[0.5,2]` 检查正常算术，当前代码与此一致。但v2.1的Q2.30表示域仍是 `0<alpha<4`，v1.4 §9.2 把较窄范围列为待纳入profile；项目合同版本仍需同步。不能将缩小接受域也称为“只收窄位宽、全合同无行为变化”。默认顶层alpha=1不受这个范围差异影响。

### 3.4 时序取数方法的裁定

保留的 `/tmp/sta_budget_out_fixed/paths/` 可复核旧网表的单段数字setup，例如：

| 路径 | arrival / required / slack |
| :--- | :--- |
| 调度ACQ寄存器 → 采集ID寄存器 | 3.21 / 24.67 / +21.46 ns |
| 事件序号寄存器 → post状态寄存器 | 2.84 / 24.72 / +21.88 ns |
| post寄存器 → post端口 | 0.38 / 23.70 / +23.32 ns |
| final_applied寄存器 → arm端口 | 0.94 / 23.70 / +22.76 ns |
| final_post寄存器 → Wm寄存器 | 4.76 / 24.68 / +19.92 ns |

这些有实际路径，不是早期仅Q→D保持自环的报告；但不能累加或改名为整个采集、RA或捕获阶段的实际耗时。`25−slack`包含各路径自己的setup、I/O、uncertainty等要求修正，不等于纯组合延迟；STA也不会通过 `-through` 自动跨多级寄存器组成阶段。

单端口路径可以也应该被约束和报告，并非STA只能做reg→reg。旧报告后续部分已有I/O路径，不能笼统认定都没约束；要检查每份网表自己的SDC、实际驱动、负载和未约束端点。25 ns是外部采样周期，内部逐事件处理、流水启动间隔和宏窗口还需独立时序合同。当前单角setup结果不证明整核40MS/s吞吐。

这不只是缺一张报告：`sar_evt_v21` 每个clk边沿最多消费一个已决事件，而普通转换包含Flash及六次SAR决定。若将这个唯一内部clk也直接取为25 ns，就不能由一个寄存段通过setup推出整笔事件在25 ns内完成。内部事件节拍与外部采样节拍需要明确对应，不能混称同一个“40 MHz通过”。

本轮查看 `/tmp/dcworkB`：仅有SVF和综合日志，过 `STEP_ELAB_OK` 后没有完成网表或STA，观察时未见相应DC进程。只能写“未取得完成结果”，不能据日志沉默断言OOM、工具崩溃或某种RTL写法必然不支持。旧PPA数值不适用于bb96361；仍可作为绑定旧版本的历史记录，不应删除原始证据。

## 4. 三个修复 A/B/C 的独立判断

| 修复 | 裁定 | 理由与限制 |
| :--- | :--- | :--- |
| A：LUT initial改case | **正确，应保留** | 当前64项case、`878a348^`旧initial表、Python LUT逐项完全相同。本轮独立确认64/64一致。case组合查表避免依赖该流程忽略的initial语义。数值一致可证，“历史上一定由脚本提取而非手抄”不能仅凭一致性认证，但不影响数值裁定 |
| B：IDLE取实际角色补集 | **正确关闭稳态旧反例；沿前语义有边界** | 8/8/1已变8/8/2，复位为8/0/10；有效CONV在capture/hold/quiet完成前不被补集列为IDLE。无需重新使用旧前瞻sched_idle |
| C：不同消费者使用不同延迟快照 | **数值修复正确；valid旁带有隐患** | A/B版本不是错误设计，消费者所在流水级不同本就需要不同延迟。当前合法域固定流水的5场景数值正确；倒数valid未与数据同相，见R3。可局部调整旁带与断言，不需要推翻七级算术架构 |

修复B的额外边界：`acq_conv_ctx.sv:386–410` 在受理沿前会发布新ACQ，而CONV寄存器尚是旧笔；若同时释放旧A并提升B，新ACQ C与旧CONV A可能在沿前短暂交叠。已有 `A=000ff,C=040fe` 的静态交集为 `000fe`，沿后分区正常。旧A已满足释放资格，**这不是本轮已证明的模拟保持破坏**；但需要说明宏何时消费角色和写门，不能把补集构造当成全周期ACQ/CONV互斥证明。该项为静态接口边界，本轮未执行模拟或RTL新反例。

修复C的实际数据时间线（n为受理沿）：

| 沿 | A的状态 |
| :--- | :--- |
| n | S1a锁存raw相关差值、alpha/G/Wm/Wp、tag、valid |
| n+1 | S1b形成Z及后续权重版本；倒数数据级无条件采到G1a=A.G |
| n+2 | N(A)形成，倒数侧继续推进A的数据 |
| n+3 | 修正倒数I(A)形成，N继续延迟 |
| n+4 | N(A)/I(A)汇合；此时部分用例ri_valid仍未正确对应 |
| n+6 | A退休，即按包含受理沿计的七个寄存沿 |

目前这一固定路径可以长期维护，但应给各阶段明确payload/valid约定与同笔断言。统一结构体是可选实现风格，不是证明正确性的必要条件；不应仅因使用A/B快照就要求大重构。

## 5. 内部权重表结构变更风险评估

| 问题 | 结论 |
| :--- | :--- |
| 权重是否可视为静态标定值 | 可以。论文与当前合同允许片外求系数、片上应用；“静态”应明确为一个运行epoch内不变，而非永不更新 |
| 一拍一字、360字够不够 | 对单时钟、始终可受理的合法地址写口，带宽足够完成初始化；若配置时钟40MHz，纯写入最少9µs。该数字不包含校验/生效，也不推导内部事件时钟必须40MHz |
| 数据寄存器无复位是否允许 | 允许，但应有复位后的无效状态和加载资格。不能把“无复位数据阵列”与“完全没有配置状态保护”混为一谈 |
| 复位期间是否应禁止写 | 不可一刀切。当前I4b在转换控制仍复位时写表，符合一种合理启动流程；应明确配置域/转换域复位关系，而非随便加rst_n门控破坏已验证加载 |
| 未灌满就发交易 | 目前可能读未初始化状态，也可能只用已写片而看似正常；代码不可靠拒绝。见R1 |
| 运行期更新 | 当前写口允许，多个字非原子；调用方“不要这样做”尚未落实合同所要求的核内保护 |
| 是否改变对外接口 | **明确改变。** 从连续数组输入变为有历史状态的编程协议，旧TB、综合网表、形式参考和宿主都必须按版本适配 |
| 是否自动降低综合复杂度 | 不能保证。新增14400个数据存储位，8片并行读的选择需求仍在；端口数降低是确定的，面积/读MUX/收敛效果需同版报告 |

最低接口应明确地址和数据稳定时点、非法写处理、写齐和范围检查、生效条件、运行期写策略、冷/暖复位语义以及epoch。它可以保持很小，不要求增加完整产品配置系统。

## 6. 对委托方五个问题的回答

**Q1：修复C是正确设计还是补丁？** 数值对齐的修法成立，不同消费者使用不同延迟版本是正常流水设计。隐患在于倒数valid和数据未同相、当前正确性依赖无条件推进；修旁带合同和断言即可，不据此要求重写整条算术链。

**Q2：内部权重存储是否引入新风险？** 是：初始化、部分装载、运行中混权、复位和跨代成为生产接口的一部分。无复位本身可接受，缺少明确的配置有效/生效协议不可被表述为已有保护。

**Q3：RTL检查是否系统性漏了一类错误？** 现有集合强于最初的固定输入测试，但主要证明合法、已准备好的数据路径。明确漏项是配置生命周期/错误资格、部分声明位宽的抽取变化、valid与数据关系，以及新接口的同版门级/形式覆盖。旧20个Formal失败本身不证明一定漏了某类RTL功能错误；它与这些已确认的覆盖缺口应分开处理。

**Q4：20个wsum failing是真问题吗？** “该次比较失败”是真事实；“当前bb96361的wsum逻辑有同一错误”证据不足。旧版本的测试接反已纠正；正确有限回放与旧Formal失败可同时存在。缺少冻结的全部参考源及可审阅反例，不能选择“综合器错”“数组错”“域外输入”之一当根因。新的内部存储架构更不能用旧外部数组网表直接作等价验收。

**Q5：只能做一件事提高可信度，做什么？** 固定bb96361，完成一次“配置装载→生效→受理→采样/重构”的生产路径验收，要求错误配置不能产生正常测量结果，并保存同版原始证据。这比继续调整算术或反复跑未固定输入的综合更直接消除当前最大风险。
