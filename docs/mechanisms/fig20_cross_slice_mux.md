## 1. 图面结构

```
 353 SHUFFLER ──┬─▶ Shuffler Pointer
 CONTROLLER     └─▶ mux_sel ────────────────┐
                                            │
  15x2C ──▶ [ 352 shuffler ] ─┄虚线┄▶ ┌────┐ │
              ▲ 标 `0` ×2              │MX1 │─┼──▶ DS1 的 2C
  另一路 ──────────────────实线────────▶└────┘ │
                                       ┌────┐ │
                                       │MX2 │─┼──▶ DS1 的 2C
                                       └────┘ │
                                       ┌────┐ │
                                       │MX3 │─┼──▶ DS1 的 2C
                                       └────┘ │
                                       ┌────┐ │
                                       │MX4 │─┼──▶ DS1 的 2C
                                       └────┘ │

```

| 元件 | 读出 |
|:---|:---|
| **353** SHUFFLER CONTROLLER | 产出 `Shuffler Pointer` 与 `mux_sel` |
| **352** shuffler | 输入 `15x2C`（= 30C），带**两个**标 `0` 的方框 |
| **MX1–MX4** | **2:1 MUX**：上输入来自 352（虚线）、下输入来自另一路（实线） |
| DS1 | `2C 2C … 2C` + 虚线框内 `C C` + 桥接 `C` |

## 2. 关键语义：分配粒度是**单元**，不是**片**

图上每个 MX 只把**一个** 2C 单元送到 DS1。所以：

> **同一片的 15 个 2C 单元可以分别来自不同路径。**

这条推翻了"跨片分配 = 整片交换"的直觉读法 —— 如果那样，图上只需一个整片的
多路开关，而不是每单元一个 MX。

对应判据：

```python
per_unit_not_per_slice(per_unit_source=[[0,1,0,1],[1,1,1,1]], slice_size=4)  # True
```

## 3. 四条判据

| # | 语义 | 判据 |
|:--:|:---|:---|
| ① | 分配粒度是单元 | `per_unit_not_per_slice` |
| ② | 每个 MX 只从两路里选一个 | `mux_selects_from_two_inputs`（`MUX_INPUTS == 2`）|
| ③ | 选择的单元数 = 该片参与分配的主单元数（15） | `selection_is_complete` |
| ④ | `Shuffler Pointer` 每笔前进 | `shuffle_pointer_advances` |

## 4. 与既有 `fig21_bridge` 的关系

仓库里的 `control/fig21_bridge.py` 是**早前的一套桥接解码规则**，其解码方式
当时已被证伪并保留为历史模块。本轮确认：

* `map_fig21_bridge` **不在主链**（只被 `control/__init__.py` 导出，`pipeline` 不调用）；
* 本模块与它**不是同一件事**：`fig21_bridge` 讲的是子阵列桥接后的等效权重，
  本模块讲的是主单元到切片的 MUX 选路。

两者可以共存，不会互相覆盖。

## 5. 明确不做的

* **不给 `mux_sel` 的具体序列**：图上只有一个标 `0` 的选择端符号与 `mux_sel<…>`
  总线名，没有真值表或状态机；
* **不接主链**：接入需要先确定分配算法（这是设计输入，不是"照图抄"）；
* **不声称已实现跨片分配**：只交付上述四条判据。
