# ISSCC 2024 §9.8 数字 IP：D1–D6 复现状态与本轮核验

对外复核基线：`952eddc`　本轮基线：`d3d4c85`　本轮交付见 §六
核验日期：2026-11-15　分支：`merge/adi-repro`

---

## 一、一句话说明当前 IP 能做什么

`d3d4_ip` 是一个**单时钟域、可综合的 DEM/Dither 开关命令生成器**：
输入 RDAC 码 `k`（0..520）与 6 位 dither 字，输出 8 片 × 20 单元的
160 位物理开关 mask、8 片 × 4 位的采样预置 pre，以及 18 片池的
ACQ/CONV/IDLE 片组划分与物理片号。

**它不输出 20 位数字码。** 权重重构（D5）与顶层事务控制（D6）
不在本 IP 内，见 §三。

本轮修掉三个会导致**硅片行为错误**的问题：逐事件 mask 错位一拍、
`ready=0` 时仍推进事务、错误标志与 mask 不同拍（§四）。

## 四、本轮确认的问题、修复与保留

### 4.1 问题 1：逐事件 RDAC 更新错位一拍（**已修复**）

**现象**：`follower_rt` 的 `k_q` 在 `bit_valid_i` 那一沿寄存，
而 `d3d4_ip` 在同一沿用 `k_use`（= 寄存的 `k_ev_w`）驱动组合 mask 并锁存。
同一沿上可见的 `k_ev_w` 仍是**上一个事件**的值。

**实测证据**（`tb/tb_event_align.sv`，修复前）：

```
EV0 idx=8 | k_ev=1   | mask[0][19:16]=0000   ← mask 仍是复位值
EV1 idx=7 | k_ev=3   | mask[0][19:16]=0100   ← 0100 是 k=1 的子阵列
EV2 idx=6 | k_ev=7   | mask[0][19:16]=0110   ← 0110 是 k=3 的
```

**修复**：`follower_rt` 增加组合口 `k_ev_comb` / `err_ev_comb`（与 `k_q`
的更新公式同一表达式），`d3d4_ip` 事件模式改用组合值。

**验证**：
- 修复前 9 个事件**全部报错**；修复后 18 个事件（连续 + 插空泡）**0 错误**
- 最后一事件后不发假判决，`repeat(3) @negedge` 确认 mask 停在该事件值
- 已接入统一入口为 L2.6

**未放宽任何判据**：原 `tb_d3d4_ip` 的 smoke 判据（k 增长 8 次/mask 改变 8 次）
保留不动，但**不再作为 D2 的证据**。

### 4.2 问题 2：`ready_o=0` 时事务仍被推进（**已修复**）

**现象**：`adv = sample_adv_i & valid_i & reset_n`，**漏了 `ready_o`**。

**实测**（事件模式 `ready_o=0`，上游误发 `valid_i=1`）：

```
valid_i=1  ready_o=0: acq=03bd00 conv=0000ff   ← 片组在推进
valid_i=1  ready_o=0: acq=0040fe conv=03bd00
valid_i=1  ready_o=0: acq=039701 conv=0040fe
```

**修复**：`assign adv = sample_adv_i & valid_i & ready_o & reset_n;`
**验证**：片组稳定在 `0000ff / 000000` 不再推进。

### 4.3 问题 4：错误标志与 mask 不同拍（**已修复**）

**现象**：`k_range_err_o` 是输入组合判断，`mask_o` 是寄存输出，差一拍。
连续 520→521→520 时，下游在 mask 有效的拍读到的是**下一笔**的标志。

**修复**：新增 `out_valid_o` / `out_k_err_o`，在输出寄存的同一 `always_ff`
里与 `mask_o` 同沿锁存；无新事务时 `out_valid_o` 落回 0，`mask_o` 保持。
原 `k_range_err_o` 保留为"入口即可拒绝"用的兼容口，文档明确它**不属于**
mask 那一笔。

**验证**：520/521/520 三笔标志与 mask 同拍对齐；空泡拍 `out_valid_o=0`
且 `mask_o` 保持。

### 4.4 问题 3：follower 与合同差异（**未修复，已定性**）

| 项 | 当前实现 | 合同 v2.1 | 影响 |
|:---|:---|:---|:---|
| 事件数 | **9**（idx 0..8，done 在 idx==8） | **Flash + 6 SAR = 7** | 多 2 个事件，时序预算错 |
| 符号 | `k = prefix − U`（`diff_s = acc_s - up_s`） | `k = c + U` | 与 `dither_pre` 的 `+U` 相反 |
| k 位宽 | **9 位**（0..511） | 需覆盖 guard 512..520 | 事件模式下 guard 不可达 |

**为什么本轮不改**：改动会波及 5 个 TB（`tb_follower_rt` / `tb_follower_int` /
`tb_dem_cov` / `tb_neg` / `tb_digital_top_w`）与 `digital_top_w`，
属于**跨模块迁移**，须由对应负责人按 §五.3 整体迁移（事件数+符号+位宽
三者同时改），不能只翻一个加减号。

**旧 6246 事件回归**：作为**旧协议兼容性**证据保留，实测仍绿
（`tb_digital_top_w` 8509 笔 PASS）。它**不能**用来论证新合同已闭合。

### 4.5 保留成果（未改动）

| 项 | 状态 | 说明 |
|:---|:---|:---|
| 叶子级 133,376 组逐位对拍 | ✅ 仍 PASS | D3/D4 叶子正确性的主证据 |
| bridge 66,688 组等电荷 | ✅ 仍 PASS | 与 133,376 组**验证对象不同**：前者只查名义电荷守恒，后者查 160 位逐位 |
| round-robin 相位发生器 | ✅ 保留 | 面积/时序/统计证据见 `docs/PHASE_AB.md` |
| 整码模式 512 笔 | ✅ 仍 PASS | 回归基线未动 |
| 旧链 8509 笔 | ✅ 仍 PASS | 兼容资产，适用版本 = `digital_top_w` + 4+3+2 + `c−U` |

**未为了保持 PASS 修改任何金标或降低检查强度。** 新增的 L2.6 是**加严**。

## 五、DEM / Dither 按完整机制核验

### 5.1 bridge：等电荷成立，但只在 β 参与时

- 主侧一个 4Cu 半单元：名义 `w = 1/4`（合同 §3.2）
- 子侧 8 片 × 4Cu 支路：`8 × (1/32) = 1/4`
- **两者相等**，穷举 66,688 组 0 违例

**踩过的坑**：第一次用"物理 Cu 数直接相加"（主 4Cu vs 子 8×4=32Cu），
得到 33,280 组"不守恒"，看起来像严重 bug。错在把 β 当成 1 ——
子阵列必须先乘 β=1/8 才能与主侧同量纲。**同一个 mask，用错权重口径
会得出完全相反的结论。**

**未按 PPT 箭头外观改**：p.31 图 A 的绿箭头两端是 4 与 8（不等权），
合同 §6.1 原文"**禁止交换不等权的完整 8 单位与 4 单位后声称守恒**"。
所以不照图改，用等电荷 E 实现。

**失配条件下**：必须按交换后的真实 mask 算 `Wm`，不能用名义守恒抹掉
实际权重变化。旧链 `algo_chain.py` 已按实际 mask 累加，本轮未改。

### 5.2 相位序列：round-robin 是工程变体

- [A] PPT p.29–31 写的是 `Round robin shuffler`，**与 `3b horizontal segmentation` 并列**
- [A] **没有公开** 1920 状态的联合序列
- [E] 本工程用"单一索引线性递增 + 混合进制分解"实现，周期恰 1920 拍

**已证**：χ²=0、MI=0、周期内零重复、面积比 xorshift 小 5.1 倍。

**未证 / 待查**：
- 1920 个**原始元组**均匀 ≠ `h[2:0]` 截位后的**控制**均匀，也 ≠
  实际物理 mask 的均匀（需统计真正进入 DEM 的 `h[2:0]`、`v`、`half`、`coin`）
- 确定性周期 1920 拍的实际采样准备推进率下的频率、自相关、杂散：**未测**

**结论**：保留 round-robin，但定位为 **[E] 工程变体**，不是原文序列复现。

### 5.3 Dither：符号是否等效未证

本工程定义（按当前位编号）：

```
f  = 4·D3 + 2·D2 + D1
U  = 4·D6 + D4
Ld = 2·D5 + f/8
T  = U + Ld
```

| 项 | 状态 |
|:---|:---|
| 512 组 pre-mask 逐位对拍 | ✅ 只证明"字 → 开关"译码 |
| `U`/`f` 与参考一致 | ✅ |
| 名义恒等式 `y/G = x − D(c+U) + TΔ` | ⚠️ 只在参考模型里成立，**未在 RTL 链上验证** |
| dither 字由哪里生成 | ❌ **由外部 `dither_i` 给，片上 PRNG 未接入** |
| 状态何时推进/保持 | ❌ 未定义（当前是纯组合译码 + 输出寄存） |
| SADC Lower 是否真实施加 | ❌ 行为宏未接（`pre_o` 只到开关层） |
| 去扰是否接入重构链 | ❌ 新 IP 无重构链 |

**符号等效性**：[P] Fig.19 是七片 worked example、粗码**扣** upper；
本工程八片、**正向注入** `k=c+U`。两者是否等效**必须核对完整路径**
（预置 → k → 残差 → 最终扣除），**不能局部改号**。本轮**未证**。

## 七、剩余依赖与下一步最小工作

按依赖顺序：

1. **重综合 + 门级等价**（必须）。本轮 RTL 已变，`SYNTH_D3D4.md` 的
   3017 cells / 2.82 ns 对应旧版本，**不能沿用**。
2. **ACQ/CONV 双上下文**（D6，跨负责人）。当前只有片组掩码，
   没有"冻结本笔 pre/qid/相位/coin/系数 epoch"的上下文寄存器。
3. **follower 协议整体迁移**（D2，跨负责人）：事件数 9→7 + 符号 `−U`→`+U`
   + 位宽 9→10。三者必须同时改，并补非零 U、Flash 边界、guard、
   首事件错 qid、乱序、重复、缺位测试。
4. **dither 片上生成与去扰**（D4）：`dither_i` 目前纯外部输入。
5. **D5 接入新 IP**：让 `d3d4_ip` 能输出 20 位码，才算整链闭合。
