# AD4080 连续原始结果搬运

[结果搬运模块](./ad4080_result_transport.sv) 把核心时钟域的 20 位结果和本笔单双 lane、固定测试字选择一起移到 I/O 时钟域。默认八格异步 FIFO，I/O 域还有一帧装载寄存器。每个有效 I/O 拍提供 DA 和 DB 的两对 DDR 装载位。现有组合映射 `ad4080_ddr_edge_words` 在模块中例化一次。[位序和 I/O 原件依据](../io/SPEC.md)

## 端口合同

| 接点 | 合同 |
| --- | --- |
| `clk_core_i` | 在上升沿提交 `result_valid_core_i` 与 `result_core_i[19:0]`, `dual_lane_core_i`, `intf_check_core_i`。连续为高表示每沿都有一笔，无源端反压。 |
| `core_online_o` | 本域与对侧均已释放本次共同复位。上游须等该状态并完成自身新会话的有效门控与流水复位，再送新结果。该状态不做停钟检测。 |
| `core_full_o`, `core_accept_o` | 在线时暴露保守满与本沿能否接收，写入前取样。因读指针同步延迟，已释放的格子可能数拍后才能再写。 |
| `core_drop_o`, `core_overflow_o` | 核心本地复位释放后，等对侧上线或已上线满写的拒收均使 `core_drop_o` 在采样沿后报告一个核心周期。用该提交沿前的 `core_online_o`、`core_full_o` 区分启动和满写。`core_overflow_o` 只由已上线的满写置位，保持至会话冲刷。硬复位和核心侧同步释放期间不采样输入，也不产生丢弃诊断。若需跨共同复位保存诊断，由常开状态汇聚。 |
| `core_drained_o` | 受理字均完成逻辑末槽装载且退休指针已回到核心域，同沿有新受理时抑制。BIST 或电源接管前，来源先停止新提交并清空上游流水，再联合该信号与实际 PHY 空闲确认。 |
| `clk_io_i`, `io_online_o` | `clk_io_i` 是上层已定位的连续 DDR pair 装载拍。宏接口在其上升沿采样本拍的 `io_pair_valid_o` 和有效负载。 |
| `io_start_allow_i` | I/O 域的新帧领取许可。许可高且有可读头字时，空闲或发末槽的本沿可装下一字。许可低时已开始的帧继续走完。若要取消在途帧，走共同复位和物理隔离。 |
| `io_pair_valid_o`, `io_first_o`, `io_last_o` | I/O 接收端每沿采走有效槽。`first/last` 对应槽零、槽 9（单 lane）或槽 4（双 lane）。输出无 `ready`，复位或失电由端口隔离处理。 |
| `io_{da,db}_{fall,rise}_o` | 一槽由下降及其随后的上升装载位组成。`io_dual_lane_o`, `io_intf_check_o` 与该槽同行且全帧冻结。`valid=0` 时位与控制标记为零，单 lane 时 DB 位为零。差分电气、DB 高阻和 lane 发射许可来自 PHY。 |
| `FIFO_ADDR_WIDTH` | 1 至 30，逻辑容量为 `2^FIFO_ADDR_WIDTH`，在发寄存器另占一帧。默认 3 的八格构型完成定向回归。实现中按物理成本选小深度。 |

接受沿填写完整 `{test, dual, word}` 到一个字槽。写指针通过两级同步宣布字槽可读。I/O 侧只在装载帧时释放队列格子，帧数据与模式从首槽保持到末槽。读指针用于归还格子，退休指针则在最后一对边沿位被逻辑装载时递增。任一方向同步延迟均只推迟观察新动作。FIFO 结果不含转换编号，若满丢弃发生，系统须依据溢出状态决定何时重新同步采集与读出对应关系。

数字回放中，队列领取总数与末槽退休总数最多相差一个在发帧。核心域在同一时钟沿观察两路返回指针的理想同步模型下，已受理总数比返回的退休数最多超前 `FIFO 深度 + 1`，小于指针模数 `2 × FIFO 深度`，本沿若有新入队也会撤销 `core_drained_o`。物理验收须检查已同步的领取计数领先已同步退休计数小于 FIFO 深度，确保核心已受理与退休快照的差不足一个完整回绕。实际接管还须确认 PHY 已发完。

### 槽推进与同沿优先级

| I/O 上升沿 | 当沿被 PHY 采走的逻辑槽 | 沿后状态 |
| --- | --- | --- |
| `J`，当前空闲且头字可取 | 无 | 领取整个字，下周期首槽可见 |
| `J+1` | 本字槽 0 | 前进到槽 1 |
| `J+K`，`K=10/5` | 本字末槽 | 退休本字。若 `io_start_allow_i` 高且队列有下一字，同沿装入并置槽零 |
| `J+K+1` | 已续接的下一字槽 0 | 形成连续 10 或 5 拍的下一帧 |

复位或失电优先于写入、领取和槽推进。无复位时，末槽和领取可以同时成立，前者归档旧帧，后者更新在发寄存器。末槽无下一字则当前帧退休并转空闲。I/O 时钟停止且供电稳定时，装载位保持，槽指针冻结；核心继续产出则填满后产生可见丢弃。两个时钟都重新运行后，稳定供电下继续同一会话。若停止时发生复位或失电，则按新会话重启。

## 复位、供电和禁止跨会话旧数据

外部 `core_reset_ni`、`io_reset_ni`、`power_good_async_i` 中任一为低，同时把整条链路拉回冲刷。电源资格由常开时序管理，在任一物理域失效前有效撤销。共同置低可在任一时钟停止时起效，两侧各以两级链同步释放，再以两级链同步接收对侧存活位。任一侧停钟期间，新会话只能等待。

复位清除双方 Gray 指针、同步器、在发帧、有效门控与溢出状态。数据阵列仍可能保有旧位，但新会话只有重写并同步递增写指针后才能读这些地址。上游要同步冲刷本身的结果流水或按会话屏蔽迟到结果。PHY 应撤销尚未发出的旧装载数据并重建帧对齐，外部接收端需要知道当前会话已中断。已上引脚的边沿无法撤回。

## CNV、时序、CDC 与物理交接

Rev. B 图 74/75 的 40 MSPS 连续 LVDS 使用单 lane 400 MHz/10 拍或双 lane 200 MHz/5 拍，每帧占 25 ns。第 48 页、图 79/80 给出 `tCYC + tMSB` 的首次内部可用预算。`tMSB` 最大 22.4 ns，默认增益时最大 18 ns。商用器件例子中，从 CNV 到首位的目标相位为单 lane 51.25 ns（启用增益校正）或 46.25 ns（默认增益），双 lane 200 MHz 的校正例为 52.50 ns。默认增益的双 lane 例按 5 ns 时钟重算为 52.50 ns，第 48 页同时出现 400 MHz 的文字，仍应以真实波形关闭歧义。[ADI Rev. 本模块的计时从提交结果沿开始。在时钟已在线、无排队、无许可阻塞的 RTL 理想情况下，刚跨域的写指针在第 2 个后续 I/O 沿可见，第 3 沿领取整字，第 4 沿采首槽。队列、启停及真实同步变化会改变等待。依照目标 CNV 与 CLK 相位，系统在首对预定装载沿的前一沿提供领取许可，且需预先保证头字可见。固定的 CNV 到数据延迟、由 `0x16[7:4]` 配置的计数、`tCCA`、实际 DCO/CLK 到 Dx、ODDR FALL→RISE 装载顺序和接收眼图由上层闭合。若宏以 RISE→FALL 为配对单位，接线层必须提供交错重排。滤波、Manchester、结果 FIFO 读记录和配置 SPI 走其各自的控制通路。

若 `result_valid_core_i` 要到手册内部最晚可用时刻才出现，启用增益校正的 40 MSPS 例从 `47.4 ns` 到首发相位只剩单 lane `3.85 ns` 或双 lane `5.10 ns`。空队列本搬运器到首槽采样就需约 `3–4` 个 I/O 周期（单 lane `7.5–10 ns`，双 lane `15–20 ns`）。部署使用实测的核心结果时刻、CDC 和物理装载预算重新核对首发相位，必要时采用更晚的合法对齐设置。满速率仿真验收的是持续吞吐和正确顺序。

| 实现对象 | 约束与签核要点 |
| --- | --- |
| `write_gray_q` → `write_gray_io_s1_q`，`read_gray_q` / `retired_gray_q` → 各核心域 `s1` | 仅 Gray 码过域。在目标 STA/CDC 中对这些总线的源寄存器到一级同步器施加有约束的最大数据延迟和位间偏斜，确保一个源递增窗口横过时不会混叠到下次变化。限值依据各源最短周期及走线裕量。全局异步 `clock_groups` 可能盖掉这类检查，加载 SDC 后逐端确认约束生效。 |
| Gray 第一级 → 第二级及存活位同步链 | `ASYNC_REG` 是布局意图。检查目的域建立、保持、物理放置和间距，依据目标库、时钟和事件率计算 MTBF。第一级只驱动第二级，功能逻辑只使用第二级。 |
| `fifo_memory_q` 数据 → `frame_q` | 数据总线依赖端口所有权而整体跨域。数据及模式必须在写指针同步后触发的领取沿前稳定。理想空队列中，核心写入和最早领取之间至少相隔约两个目的域周期。按最短 I/O 周期（样例 2.5 ns）和余量为真实数组、读地址和选择器路径分配约束。CDC 审计同步器和数据保持证明一并检查。 |
| 复位树和供电 | 串行释放同步器、异步 OR/AND 复位树的无毛刺、低脉宽、恢复/撤销时间和跨域同时失效须验证。目标多电源设计需合适的隔离钳位、level shifter、PG 与上下电 UPF。`power_good_async_i` 的撤销须在物理数据不可靠前到达。 |
| PHY 和 STA | 将逻辑采走沿及 DA/DB 对交给实际 PHY/ODDR。确认时钟树、相位、输出使能、P/N 和回波，使用目标库及封装/板载荷检查建立、保持、输入占空与眼图。若允许停钟，进一步定义完成或中止条件。 |

本轮的通用综合与数字仿真覆盖接口功能。实硅 CDC、RDC、PVT、真实库与布局后的 IO 相位仍待签核。满速时理论生产率与服务率相等，较长时钟停摆或持续频差会耗尽空闲格子并触发丢弃诊断，部署时以端到端时钟和队列预算选择深度。

## 外围壳层接点

本模块适用于连续原始结果。一次装配应把该模块已经输出的装载对直接交给硬 PHY，保证同一路只经过一次位序映射。已有外围壳层的全帧并行边沿字端口是另一抽象层。若从单口 SRAM 的无回压读返回提取数据，必须在发读前预留 FIFO 容量或提供滞留缓冲，并处理测试模式抢占、读回命令与 reset/flush；这些行为由装配层验收。复用现有映射外，本工作包的验证载荷均由独立测试台产生。

## 本地复跑和证据

在交付根执行，`PATH` 需能找到 Verilator、Clang C++20 和构建所需命令。

```sh
sh ./transport/verify.sh
```

通过 `TRANSPORT_VERILATOR` 可指定其他预装 Verilator 可执行文件。如果选用 `verilator_bin`，按该安装设置 `VERILATOR_ROOT`。用 `TRANSPORT_YOSYS` 指定 Yosys 可执行文件可追加通用综合和网表检查。临时构建目录由脚本输出。回归按 40/400 MHz、40/200 MHz 分别连续重组 512 笔，再用 2.52 ns I/O 周期相对核心时钟滑相重组 160 笔混合模式结果，另测试两种空起首槽时刻及单 lane 服务过载下的保序和丢弃结算。要单独重放启动期丢弃，将 `+transport_startup_drop` 传给脚本产出的测试程序。对比修前时在临时副本用备份 RTL 替代搬运模块，保留同一测试台和映射器。[独立接收与激励](./tb_ad4080_result_transport.sv) · [执行回执](./verification.txt)
