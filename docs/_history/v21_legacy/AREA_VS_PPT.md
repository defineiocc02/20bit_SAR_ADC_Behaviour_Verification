# 面积对比：本工程 vs ISSCC 2024 9.8 原型

时间：2026-11-16　原型：40nm ULP　本工程：TSMC 28HPC+

## 1. 原型公布的数字（PPT p.40 / p.42，论文 Fig. 9.8.7）

| 项 | 原文值 | 出处 |
|:---|:---|:---|
| 工艺 | **40 nm ULP** | PPT p.40 |
| 核心面积 | `A_CORE = 0.77 mm²` | PPT p.40 |
| 核心 + 参考缓冲 | `A_CORE+REFBUF = 0.9 mm²` | PPT p.40 |
| 芯片尺寸标注 | 1050 µm × 820 µm | PPT p.40 |
| 功耗 | ADC core **50 mW**，整芯片 69 mW | PPT p.42 |

## 2. 原型数字区域：图估约 0.060 mm²

PPT p.40 左上窄条明确标为 **Digital**，位于 Quantizer 上方、面向 RDAC。
按同图标尺分别校准两轴：

| 量 | 图上测量 | 标尺 | 换算 |
|:---|:---|:---|:---|
| Digital 宽 | 约 37.20 PDF 点 | 315 点 = 1050 µm | **124 µm** |
| Digital 高 | 约 129.48 PDF 点 | 218.21 点 = 820 µm | **487 µm** |
| 区域 | 124 × 487 | — | **≈ 0.060 mm²** |
| 占比 | 0.060 / 0.77 | — | **≈ 7.8%** |

**这是图上区域估算，不是标准单元面积。** 原文没有单列数字面积，
也没有披露红框内的全部模块归属。

不能做的两件事：
- 不能按 `(28/40)² = 0.49` 直接缩放成 0.029 mm² 当目标 ——
  库、位宽、存储实现、布线和时序约束都不同。
- 不能把 0.060 mm² 当作**完整数字系统**（含 SPI/FIFO/滤波/PHY）的预算。

## 4. 差距的定量判断（基于已有数据）

用 `recon_v21` 单模块 26818 µm² 与数字区域 0.060 mm² = 60000 µm² 对比：

```
recon 单模块 / 原型数字区域 = 26818 / 60000 ≈ 45%
```

**仅重构一个模块就占掉原型数字区域近一半。** 这是必须解决的 PPA 问题，
方向已经在 `c6f2309` 走出第一步（位宽 193→67、96 位除法→32 位）。

需要说明的是：本工程的 `recon_v21` 用**精确整数除法**保证位精确
（方案 §9.3 的基线要求），而原型数字区里不可能有一组 96/96 除法器。
所以这个对比不是"实现效率差 45%"，而是**算法实现阶段不同**：
本工程在保功能正确性的基线，优化路径（倒数迭代、流水、常数化简）尚未走完。

## 5. 下一步的面积收敛路径

按方案 §9.1 与审查要求"由证据驱动"：

| 步骤 | 预期收益 | 状态 |
|:---|:---|:---|
| 常数除法改乘移位（除 96） | 消除一组 96/96 除法器 | **已完成**（`c6f2309`） |
| 按实际范围收窄位宽 | 193 → 67 位乘法 | **已完成** |
| `I = RND(2^60, G)` 改倒数迭代 | 消除第二组除法器 | 未做（需证明差值界） |
| `sched18` 的 popc18 归约改写 | 消除 500 个加法器 | 未做（本轮 DC 的关键瓶颈） |
| 权重 bank 换 SRAM 分行 | 减少寄存器面积 | 未做（需先定带宽） |

`flow/synth/v21/dc_synth_v21.tcl` 用 `compile -map_effort medium` 作为基线。
`compile_ultra` 在本设计上耗时过长，暂不作为常规入口。
