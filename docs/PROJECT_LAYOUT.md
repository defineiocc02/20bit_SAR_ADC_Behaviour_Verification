# 文件放置与版本规范

本文件规定合并后的新工作应放在哪里。已有 `docs/evidence/`、`docs/reports/`
和 `tools/results/` 包含被其他报告引用、部分带哈希的历史记录，保持原位置；
它们是冻结证据，不应被移动、改写或误标为本次新跑结果。

| 内容 | 位置 | 约定 |
|---|---|---|
| Python 行为模型 | `src/adi_model/` | 模块源码和类型标注 |
| SAR 数字 RTL | `rtl/` | 模块、顶层、参数及源码清单 |
| 通用仿真 | `sim/tb/`、`sim/vectors/` | 自检 testbench 与需要版本化的小型固定向量 |
| 独立数字子系统 | `ad4080_dsp/` | 自有 RTL、模型、测试、接口与子系统文档；项目接入层位于此目录 |
| 自动化验证 | `tests/`、`tools/` | 可复现测试和命令入口 |
| 设计契约与决策 | `docs/rtl/`、`docs/adr/` | 算术、接口、架构选择及其证据边界 |
| README 图和轻量数据 | `docs/readme/fig/`、`docs/readme/data/` | 自绘图、绘图脚本、足以重画结果图的冻结数据与来源记录 |
| 专题机制与实验 | `docs/caaz/` 等专题目录 | 专题说明、原创图、轻量重画数据与脚本；大规模 raw 捕获留在仓库外，首页可引用专题图 |
| 历史文档 | `docs/history/` | 标记版本与历史状态，不把旧结论当作当前实现 |

新的大体积生成产物、仿真日志、临时编译文件应写入仓库外的单独输出目录；
例如命令中使用 `${TMPDIR:-/tmp}/sar-adc-results`、`BUILD_DIR=...`。现有
`tools/run_open_rtl.py` 的日志位于被忽略的 `sim/artifacts/open_rtl/`，这是
兼容现有入口的本地暂存位置，不应提交。需要长期留存的、体积合适的冻结向量
或证据应写清来源、版本和生成命令，不把原始论文、讲稿或专利 PDF 放进仓库。

一个集成分支应当包含已核验的历史分支提交，工作树中的未提交文件要单独
保护；分支名、当前提交、验证结果和未提交状态属于不同信息，不能因为合并
提交就声称所有旧工作树已同步或所有历史测试已重跑。
