# Cached P5 physical route at 25 ns: complete route, timing failure

Vivado 2018.3, xc7vx690tffg1761-2 OOC, one real internal BUFGCTRL_X0Y0. The same validated P5 synthesis DCP was routed. Route and DRC errors are zero; all 16 check_timing categories are zero, but setup WNS -0.280 ns and hold WHS -2.361 ns. The raw run is `BUFFERED_IMPL_TIMING_NOT_MET`, not a 40 MHz implementation success. The worst hold path is an OOC config input with zero assumed input delay; board input timing was not supplied. `internal_min_paths.rpt` currently uses a clock-group filter that includes clocked input ports, so it must not be interpreted as register-to-register hold. The route DCP is not copied into Git; its remote size and SHA-256 are in `implementation_checkpoints.json`. This directory preserves the actual raw run and byte hashes.

`regreg_followup/` is a separate read-only STA run on the *same* routed DCP. It explicitly filters from sequential clock pins to sequential data pins: 66,536 clock pins, 199,524 data pins. The genuine register-to-register worst setup is -0.280 ns (slice-select to row cache), while worst hold is +0.062 ns (slice-pool state). The follow-up does not change constraints or make the original all-path timing pass. Its six raw files have a separate SHA-256 list. The production implementation Tcl has since been corrected to use this exact register-pin scope for future internal timing fields.
