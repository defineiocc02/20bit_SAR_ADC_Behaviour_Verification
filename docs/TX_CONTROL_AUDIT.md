# 事务控制审查（第一步，基线 bf2f70b）

## 发现的四个确定性缺陷（已修）

| # | 缺陷 | 后果 | 修法 |
|:--:|:---|:---|:---|
| 1 | `busy_o` 不含事件活动 | 事件进行中 `cfg_we` 可直接改系数，**该笔事务的权重被换掉** | `busy_o` 并入 `ev_active_q` |
| 2 | `in_ready_o` 不含事件活动 | 事件进行中还能塞进整码事务，两笔状态互踩 | `in_ready_o` 并入 `~ev_active_q` |
| 3 | `ev_mode_i` 未冻结 | 飞行中切换模式，E1 会用错来源 | 加 `ev_mode_q` + `mode_eff` 组合选择 |
| 4 | `sample_cnt` 16 位，`65536 % 9 = 7` | 回绕后 9 组轮转错位 7 位 | 改用 `grp_cnt` 0..8 环计数 |

### 缺陷 3 的细节

只加 `ev_mode_q` 还不够：整码事务在接收当拍 `ev_mode_q` 尚未更新（要等时钟沿），
E1 会用到上一笔的模式。最终写法：

```systemverilog
wire mode_eff = (valid_i && in_ready_o) ? ev_mode_i : ev_mode_q;
```

- 整码事务：接收当拍按 `ev_mode_i` 决定
- 事件事务：`valid_i=0`，沿用 start 时冻结的 `ev_mode_q`

### 缺陷 4 的细节

`grp_of(sample_cnt) = sample_cnt % 9`，而 65536 不是 9 的倍数。
第 1 笔到第 65537 笔之间组号会跳变 7。
改为独立的 4 位环计数 `grp_cnt`，在 8→0 处循环，与 `sample_cnt` 解耦。

## 其余检查点结论

| 检查点 | 结论 |
|:---|:---|
| start/reset/stall/done/提交 有重复或丢失 | `ev_final_valid_q` 是单拍脉冲，`ev_start_i` 清它；reset 清全部。未见重复提交 |
| ADC2 与 tag 对应 | `ev_adc2_commit_q` 在**最后事件那拍**采样，`ev_tag_q` 在 start 冻结；同一事务 |
| 事件进行中改 cfg 系数 | 修 1 后由 `busy_o` 挡住 |
| 整码模式 `ev_mode_i` 切换 | 修 3 后由 `mode_eff` 保证当拍正确 |
