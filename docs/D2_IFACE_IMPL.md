# D2 接口显式化：实现与验证

基线 `5873183`。**不修改 D3–D5 数学，不破坏 9 事件基线。**

## 一、新增接口

| 端口 | 方向 | 说明 |
|:---|:---|:---|
| `sar_index_i[3:0]` | in | 该已决位在 9 位粗码中的位置 0..8 |
| `sar_qid_i` | in | 量化器身份 0=A 1=B，**每笔事务 start 时冻结** |
| `flash_valid_i` | in | 3-bit Flash 结果有效（start 采样） |
| `flash_code_i[2:0]` | in | Flash 最高 3 位 |
| `ev_proto_err_o` | out | 位序/重复/缺位/qid 协议违例 |

### 索引定义（0..8 的位序）

```
sar_index_i = 0  ->  原码 bit8（最高位）
sar_index_i = 8  ->  原码 bit0（子阵列最低位）
```

内部：`pos = 8 - sar_index_i`，位放到 `1 << pos`。

**索引真正参与功能**：不再是"第几个事件就放第几位"的隐式推定，
而是**由端口决定位落点**。TB 打个反序，结果立刻错。

## 二、双 SADC：只支持不重叠，非法交错报错

**明确选择：本版只支持 A/B 交替、事件不重叠。**

实现方式：

- `sar_qid_i` 在 `start_i` 冻结到 `qid_q`
- 第一个事件记下 `qid_seen`
- 之后任何事件的 `sar_qid_i != qid_q` → `proto_err_o=1`

**没有给单套状态机加一个 qid 端口就宣称双 SADC 已实现。**
真正的事件交错（两个量化器各自维护前缀/相位/事务身份）**未做**，
需要两套独立状态机，见 `D2_INTERFACE_SPEC.md` §3。

## 三、Flash 通道的定位

`flash_valid_i=1` 时，`prefix_q` 初值预置为 `{flash_code_i, 6'b0}`
（即最高 3 位已定）。后续 9 个事件仍照常送入。

**这是接口预留，不是"Flash 替代前 3 次比较"。**
真正用 Flash 结果省掉 3 个事件需要改事件数与 SAR 控制，**未做，
也不把事件数改成 7**（见 `D2_INTERFACE_SPEC.md` §1）。

## 四、协议检查项

| 检查 | 触发条件 | 输出 |
|:---|:---|:---|
| 位序错 / 重复 / 缺位 | `sar_index_i != exp_idx` | `proto_err_o=1` |
| qid 交错 | 事件中途 `sar_qid_i` 变了 | `proto_err_o=1` |
| 前缀 < Upper | 9 位无符号减法会回绕 | `ev_err_o=1`（另一路） |

## 五、验证

| 项 | 结果 |
|:---|:---|
| 事件级对拍（含逐事件 mask） | **5544 事件 0 错误** |
| 两路等价 | **64 组 0 不一致** |
| 8509 笔整码回归 | **PASS** |

### 调试中修掉的一个真 bug

`wire [2:0] pos3 = 3'd8 - sar_index_i[2:0];` —— **`3'd8` 装不进 3 位，被截成 0**。
所有事件都把位放到 LSB，`k` 恒为 1。
改成 `wire [3:0] pos3 = 4'd8 - sar_index_i[3:0];` 后通过。
