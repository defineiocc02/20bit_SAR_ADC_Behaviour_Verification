# Arithmetic audit: installed-tool startup and file-stimulus scheduling

The repaired independent audit passes on both recorded Verilator builds: **40,010 MAC cases**, **40,000 ADC cases**, **10,048 divider transactions**, and **8 output-flag sequences** per build. These are distinct coverage units. The same fixed-seed vector hashes are retained; no production RTL, expected arithmetic, thresholds, or count gates changed.

## Two separately observed failures

1. CI run `36626662809`, job `109605295575`, commit `0c4a772` completed all 21 ordinary RTL benches, including the seven-geometry reducer miter. Its next independent-audit step failed before compilation: the Python runner converted the installed header root into `VERILATOR_ROOT`, causing `/usr/bin/verilator` to look for a nonexistent runtime-local `verilator_bin`. `ci_failure_excerpt.log` preserves the relevant original log line numbers; the full downloaded log hash is in `manifest.json`.
2. After repairing startup, local official 5.020 exposed a separate file-stimulus scheduling issue. The original arithmetic TB failed at MAC line 3. A print-only diagnostic shows updated raw input and DUT input port at lines 2 and 3, while `diff`, `op1`, `shifted`, overflow, and output retain line 1 values. The generated assignment occurs only in the recorded settle function. `before_observed_tb.sv`, its log, and `generated_settle_excerpt.txt` preserve this bounded evidence. No upstream issue number or general defect affecting all uses of `$fscanf` is asserted.

The runner now preserves ASCII runtime environment settings and leaves a split installation's launcher resolution intact. It only aliases a whitespace/non-ASCII runtime when that directory contains its own executable. An explicit input-sampling event now separates file I/O from combinational DUT evaluation: the first TB capture is at 0.25 ns, the snapshot settles for 0.5 ns before the clock falls, and the original comparison executes another 0.25 ns later. Each input still occupies 1 ns. Python expected values remain associated with the raw vector row; no expected value is generated by the DUT or its sampled inputs.

## Acceptance and negative controls

- `after_5020.*` and `after_549.*` record full simulator exit 0 and exact completion counts. Their source hashes match the repaired repository files at this milestone. The 5.49 tool is the recorded development wheel, not an asserted official release tag.
- `stale_mac.patch` deliberately captures only the first fine input. The independent expected vectors detect MAC line 3, simulator return code -6 and runner return code 1.
- `stale_adc.patch` deliberately fixes the sampled ADC code at zero. MAC cases still complete; the independent ADC expected values detect ADC line 2 with the same failure return codes.
- All failed runs lack a successful manifest. The eight unit tests exercise installed/bundled runtime paths and environment preservation. Their lightweight launcher fixture reproduces old root-injection exit 127 and fixed startup exit 0; these fixture results are process-boundary tests, not RTL simulation.

The acceptance manifests contain exact tool commands, compiler flags, versions, source hashes, and vector hashes. The macOS 5.020 build needed an external `experimental/coroutine` header bridge because the local libc++ lacks that old header; the official translator is unmodified. Its existing provenance is in `../reducer_scheduler/tool_5020_provenance.json`. This archive does not claim a succeeding Ubuntu CI rerun or FPGA/ASIC timing closure.

## Reproduce

From the repository root, using the desired installed or explicitly configured Verilator command:

```sh
python -m pytest -q tests/unit/test_arithmetic_audit_runner.py
python tools/audit_rtl_arithmetic.py --output-dir sim/artifacts/arithmetic-audit
```

`VERILATOR` accepts a shell-style executable/argument string parsed with `shlex`; the runner does not execute that string through a shell. A valid caller-supplied ASCII `VERILATOR_ROOT` remains unchanged. The runner already supplies C++20 and the recorded make compatibility variables. For the local official 5.020 build only, the recorded additional flag was `-CFLAGS -I/tmp/sar_verilator_5_020_build/compat`.

For a negative-control replay, copy the repository to a disposable directory and apply exactly one archived patch to its TB; then use the same audit command. The deliberate mutants must fail and must never replace the accepted TB. The archived original runner has suffix `.py.txt` to preserve exact pre-fix bytes as evidence; it is not a maintained executable or a lint exemption.

`sha256.json` covers every file in this directory except itself. Earlier arithmetic and final-regression archives remain unchanged as historical snapshots.
