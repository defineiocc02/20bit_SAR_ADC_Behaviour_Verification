## 2. Dither：失效可被原测试漏过

基线 `dither_gen.sv` 的更新式是：

```systemverilog
{lfsr[0], lfsr[31:1]} ^ (lfsr[0] ? 32'h80200003 : 0)
```

等效反馈高位消失，默认种子推进后的前几项为 `+2,+2,0,-1,-2,-2,…`。
200000 次原映射计数是 `[-2:199996,-1:1,0:1,+1:0,+2:2]`，均值 −1.999945。
原 T6 仅检查范围及 −D/0/+D 曾出现，无法抓住稳态退化。P3 的 force dither
也绕过了内部源，因此链路逐位比对不能覆盖此问题。

单纯改成零补位还不够：一步一取样时高字节窗口重叠，D=2 相邻相关系数约 0.50。
修复采用每个 enabled draw 推进 8 位。周期 `2^32−1` 与 8 互素，不缩短非零状态周期。
`tests/unit/test_rtl_review_regressions.py` 独立检查 GF(2) 变换的周期及全部素因子约数。

统计分布对齐 Python sampling 分支 `round(uniform(-D,D))`：D=2 时
`[1,2,2,2,1]/8`，而非五个整数等概率。PCG64 与 RTL 序列不要求逐位相同。
Quantizer-dither 的 L3 注入向量仍是另一项验证，不能混同。

`review_dither_tb` 排除 64 拍启动段，再对每实例运行 200000 次。测试 D=0/1/2/3/63、
默认种子及 1/0xffffffff，直接断言支撑集、PMF、均值、lag-1 相关、保持与复位。
默认 D=2 实测均值 −0.004590，相关系数 −0.001488；全部 7 组通过。
这不是随机源通用质量认证，后续频谱验证还应覆盖更长记录、更多种子与周期性 DEM 的组合。

## 3. 配置：完整装载和原子提交是接口要求

以前合法 ADC2 范围即可拉高 ready；复位零权重或漏项没有进入提交校验。
修复将“每次写合法”和“整份配置完整”分开检查，只有完整图像才能提交。

集成者需要采用 [ADR 0016](../adr/0016-rtl-configuration-and-dither.md)：

1. reset/clear 后写完全部 18×71 权重与 offset/min/max 三标量。
2. 0x1018 后留出三个完整上升沿，之后才发其它写或 validate。
3. validate 与写请求互斥；冲突报错误 5，缺字段报错误 6。
4. ready 后不接受配置写；clear 终止在途重构，并要求重新完整装载。
5. 控制默认值可保留；DEM reset 默认仍为关闭，需显式写使能。

内部端口增加，但顶层端口/地址映射不变。软件依赖“只改某几个寄存器后重新 validate”
的旧操作会被拒绝；本分支不提供 shadow 双缓冲热更新。
新增 bitmap 有面积成本，需重新综合，不能沿用基线面积数字。

`review_config_tb` 覆盖缺权重/缺标量、漏一项、重复写、非法零权重、超宽权重、
写+validate、控制忙态 validate/外部写、active 写拒绝、清除在途样本与完整重载。
真实内部 dither（不 force）覆盖全部支撑码并产生 624 个输出样本。

## 4. 变异：先判断跑完，再判断观测到差异

保留 `trace_compare.py` 的公共前缀比较语义；在调用方增加完整执行过滤：

- 启动前删除本地旧 trace；远端继续使用 `--fresh`。
- 编译/环境错误、超时、传输失败不能进入比较。
- TB 仅在全部预期样本采完后写 `# P3_TRACE_COMPLETE rows=4095`。
- 标记必须位于文件末尾；样本数与索引 0..4094 必须完整；每行必须为四列。
- 接受完成后的 TB mismatch 报错，从 JSON 读取 killed/unobserved；短 trace 不算等价。
- 变异位点按唯一源码语句定位，避免新增端口/注释后行号漂移导致注错位置。

`~offset_q` 是补码取反 `-offset_q-1`，非“只动次 LSB”。两个未溢出的整数镜像反例：
非零 offset 4096→−4097 导致输出 524287→524288；即使 0→−1，也能在临界输入上
导致 524288→524289。当前向量 unobserved 不能升级为结构性等价。

## 6. 下一阶段建议：按验收门推进

**第一步：冻结当前功能基线。** 合并前检查这个 SHA 的 Python 与 RTL CI；保留
P1/P2/P3 基线和异常输入回归。新增物理模块必须给出正例、会失败的反例、来源级别、
适用域及退出条件。不能用大样本正常波形替代配置、边界和溢出测试。

**第二步：单独做吞吐与时序架构决策。** 当前每 16 拍输出一个样本，40 MS/s 要求
640 MHz，即 1.5625 ns。100 MHz 时只能得到 6.25 MS/s 的调度上限。
比较候选时同时记录 latency、initiation interval、目标 Fclk、资源和误差契约。
P=4 的 `ceil(63/4)+2=18` 不可行；P=7 的 10 ns 单模块微小正 slack 无法证明 640 MHz。
优先对除法器、568 项求和及权重访问做分层约束。若尝试倒数乘法，先分析
`gain=ΣW*a` 随 slice/mask 变化的集合，不能默认它是全局常数；必须证明并校正商误差，
保持负数 floor、极值和 clipping 逐位契约。流水化或并行重构都应先验证吞吐，
再与模拟相位预算及数据跨域关系匹配，避免只把某个延迟数字调小。

**第三步：分开补物理模型。** P09 的跟踪因果性已测，但 DA 需要有记忆的多时间常数
状态及采样历史扫描；P10 的信号相位积分/理想复位已测，但 AZ 的存储噪声、开关噪声、
相关折叠和释放过程尚未进入已验证模型。先建立可独立验证的子模型与极限情况，
再逐项接回端到端链；未披露参数保留 assumption/sweep，不能写成论文精确实现。

**第四步：扩大故障检出与签核。** 两端控制通过后再做均匀抽样 campaign，分别报告
编译失败、运行失败、未完成、killed、unobserved、有独立证明的等价项。
增加重构 offset/增益边界、状态采样时刻和跨配置版本覆盖；最后在目标工具、库、
时钟约束与 PVT 下重新综合/时序验证。每份结果都绑定源码 SHA、参数哈希与运行命令。
