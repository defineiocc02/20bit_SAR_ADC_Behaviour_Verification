# 结果 SRAM、宏交付和 MBIST

结果存储选用 **4 × 4096 × 20 bit 1RW**，总有效容量为 **327,680 bit = 40 KiB**。14 位逻辑字地址的 `[13:12]` 选银行，`[11:0]` 选银行内地址。`result_store` 已定义该数据通路。读写请求按整块存储互斥，即使地址落在不同银行。左侧 `SR2` 的用途和电源域待定，这里保留独立的 130 × 45 µm 窗口。宏尺寸和供电可行性须等目标工艺编译视图闭合。[项目规划](../floorplan/plan.json) · [单口适配 RTL](../rtl/result_store.sv)

## 1. 公开时序与内部接口

| `FIFO_MODE` | 采集行为 | 外部读出边界 |
| --- | --- | --- |
| `00` | 禁用 FIFO，复位事件布防 | 可用正常数据直出路径 |
| `01` | 立即模式，从首个有效结果起写入 `W` 字后冻结 | `FIFO_FULL` 后读 `W` 字，完成后按 `00` → `01` 重布防 |
| `10` | 事件后捕获 `W` 字，触发源为配置的内部阈值或外部 GPIO | `FIFO_FULL` 后读 `W` 字，下一次捕获先写 `00` |
| `11` | 先循环留存最近 16,384 字，触发后再写 `W` 字 | `W` 须为 4 的倍数。读出 16,384 字，首个触发后结果位于第 `16,384 − (W−1)` 字，位置按 1 起算 |

`W` 为 `0x1D/0x1E` 中配置的 WATERMARK，寄存器限幅至 1–16,384，复位值为 16,384。满深度计数用 15 bit，循环字址用 14 bit。模式由 `0x1C` 选择，主机通过 `0x14` 状态或映射 GPIO 获知捕获和读出进度。模式 `11` 在首轮写满前触发时，全深度读回含前次记录或首次上电不确定值。上电、复位和重布防只管理控制状态，未写字交给上层按有效记录范围解释。SPI 的 24 bit 符号扩展、24 bit 数据帧 CRC 和头部由接口组装，每个 SRAM 记录只占 20 bit。[ADI Rev. B 第 51–53、56–63、83、90–91 页](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=56)

在 40 MSPS 下，满深度记录窗口 `16,384 / 40,000,000` 为 **409.6 µs**，首末样本间隔为 409.575 µs。立即捕获时手册给出共 `W+3` 个 CNV 计数，满深度对应 409.675 µs 的计数尺度，边沿起点见图 86 和图 90。读出是录完后的独立阶段，采用单/四路 SPI 或单路 LVDS。从 SRAM 角度，每个被采集的有效结果产生一次 20 bit 写入，每个实际取出的字产生一次读请求。控制流水、同步头、符号扩展和帧传输分别核算时间或总线负荷。[ADI Rev. B 第 7、51–52、58–61 页](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=58)

`result_store.clk` 为本方案的 SRAM 单口仲裁时钟。捕获路径在有效结果到达时按顺序提交写操作。读出口在最后一次写操作提交后，接收用握手发布的记录快照，其中含冻结写指针、应读长度和有效范围。读命令和返回数据分别在 SRAM 域和读取时钟域之间用握手、预取和必要的异步队列传输。功能 RTL 集成必须确定返回缓冲深度、满停条件、读数归属、帧中止后的再读规则，以及独立时钟停启时的交接。FIFO 异步读出时，片外 `DCLK` / `CLK±` 和 `CNV` 的相位互不约束。若采用切钟方案，则须有无毛刺时钟选择、两侧空闲确认、最小脉宽、首个有效边沿和 STA 证据。当前 MBIST 和 `result_store` 以同一 SRAM 时钟接合。[ADI Rev. B 第 56、58–60 页](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=56)

| 上升沿输入 | 沿后响应 | 连续操作 |
| --- | --- | --- |
| `req=0` | `read_valid=0` | 地址、数据可默认保持 |
| `req=1, write=1` | 只写选中银行，`read_valid=0` | 下一沿可写另一银行，也可读刚写地址 |
| `req=1, write=0` | `read_valid=1`，`data_o` 对应该沿捕获的地址 | 可逐拍读和换银行，在下一沿由同步端消费上拍读响应 |

以 40 MSPS 全速直写作最低功能吞吐率约束，SRAM 应支持每 25 ns 至少接受一个 20 bit 写字，包含译码、写建立保持及跨域裕量。满速读接口要用最短配置下的每字服务周期核算。例如果读出采用 400 MHz 单路 DDR，每 10 个读出周期消耗一个 20 bit 字，对应 40 Mword/s。按 SPI `DCLK=50 MHz` 和 24 bit/结果，单/四路仅负载的满深度时间下限为 7.86432/1.96608 ms，帧开销另计。PVT 下的实际 `Tcycle`、`tCQ`、输出保持、首次读和电源唤醒建立从宏时序模型取得。[ADI Rev. B 第 7、45–46、51–52、59–60 页](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=51)

每银行 **290.5 × 88 µm**，可用面积 **25,564 µm²**。4096×20 有 81,920 个有效 bit，故编译宏含外围的占地密度须达到 **0.3120605 µm²/有效 bit 以下**，等价于约 **3.2045 Mbit/mm² 以上**。四银行总占框 102,256 µm²，窗口剩余 18,744 µm² 已计作该 2×2 模板的边界和通道。尺寸和引脚可达性须分别判定。示例宏 250×100 µm 面积满足上限，两个正交摆向的高度均超过 88 µm。编译到 4096×32 时仍按 81,920 个对产品有效的 bit 算达标密度，额外列、行解码、感放、冗余、边界和馈线均消耗实测面积。[几何核查](../evidence/geometry.json)

- **引脚和朝向**　功能译码和读回选择布在 `SRAM_BUS` 以南的 IP 边缘，用近宏缓冲和分支连通四银行。编译器若给南侧信号针脚并允许 X 轴镜像，可试下排镜像、上排 `R0`，让信号针脚面向 8 µm 横通道，再经列间或专用跨层连接到 `SRAM_BUS`。编译视图、井边界、tap、PG 极性和 pin access 验证后才锁定朝向。用真实针脚、层阻塞、轨距、过孔面积及阵列邻距试布，分别审核 `CLK/CEN/WEN`、12 地址位、20 写位和 20 读位的走线与时序。
- **电源和地**　建议由数字核心电源分支供 `VDD_MEM/VSS_MEM`，是否同压以及是否拆成 core/periphery 两套 PG 以宏文档为准。沿各允许 PG 边布电源条并留过孔阵列，在宏上方允许层做跨银行馈电，从数字网格回流并远离参考/采样回路。按最坏读写电流验证 8 µm 通道、静态/动态 IR、EM、唤醒峰值和模拟耦合。独立断电或多电压时核对隔离、LS、睡眠/保留状态及上电先后。ADI 公布的 `VDD11=1.1 V` 核心电源和 `IOVDD` 接口电源只可作为系统对标。这两条引脚规格未给出内部 SRAM 的实际电源归属。[ADI Rev. B 第 4–6、10 页](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=10)
- **宏替换**　请求目标 PDK 授权的 `4096×20`、同步单口、全字写宏。若以多个合法宽度拼成一银行，应统一地址与读写周期，按实际组合占框核对面积、PG、针脚和布线。保留 `result_bank_4k20` 接口，宏外包装完成有效极性、写掩码、电源状态和读出拍对齐。若宏物理位超出 20 bit，测试负责人须确认内部测试、冗余和修复能覆盖该部分资源。[现有 SRAM 叶子](../rtl/result_store.sv)

## 3. 独立 MBIST

`result_store_mbist` 是 `result_store` 前面的可综合单口仲裁器和 March 控制器。采用同域 `clk` 与低有效 `rst_n`，上层同步释放复位。`test_mode_i` 来自授权 DFT 模式，`func_quiesced_i` 表示转换写入、数据读取及预取均排空。两者以及 `start_i`、`checkerboard_i`、`func_reinit_done_i` 在本域同步提供。断钟或复位后的系统重建策略由上层负责。[MBIST RTL](result_store_mbist.sv)

| 状态或事件 | SRAM 所有权、响应与退出 |
| --- | --- |
| `IDLE`、正常启动 | `func_hold_o=0` 时转发功能 `req/write/addr/data`。`test_mode_i=1` 阻止新功能访问，转发此前已受理的读响应直至排空 |
| `start_i && start_ready_o` 有效沿 | 仅在测试模式、功能静止、无功能请求/读返回且 reinit 应答低时接受。锁存测试底图，建立内容失效标志与功能冻结 |
| `MARCH` / `DRAIN` | 每 SRAM 周期最多发一个 MBIST 操作，并在下一沿对齐读有效及数据。测试读响应仅到 BIST；最后一个读响应核对后报告 `done_o` |
| 读错误或授权撤回 | 首个数据失配或读有效协议错误转到恢复，诊断地址有效时可由 `[13:12]` 定位银行。比较沿可能已给同一测试窗口提交下一条测试命令。撤回 `test_mode_i` 或 `func_quiesced_i` 时请求立即屏蔽，下一沿报告中止 |
| `RECOVER` | 完成、失败和中止都保持 `func_hold_o` 与 `contents_invalid_o`。退出条件是测试模式低、功能静止、无功能请求、无读响应且已由上层清捕获元数据并回应 `func_reinit_done_i` |
| 复位 | 立即关 SRAM 请求，清 MBIST 状态及诊断。集成中同一次复位须使 FIFO 读写指针、快照、待发送回读与外部记录失效；物理存储保持其电源周期的实际状态 |

`done_o` 和 `fail_reason_o` 保持到下一次接受的测试启动或复位。`fail_reason_o=0` 且 `done_o=1` 表示本次通过，`1/2/3` 分别表示数据错误、读有效协议错误和中止。只有 `fail_addr_valid_o=1` 时首错地址有意义。若为缺少响应的协议错误，实际数据字段为默认零，地址和期望值仍可定位缺少的响应。

March C− 的操作次序为 `↑(wP); ↑(rP,w~P); ↑(r~P,wP); ↓(rP,w~P); ↓(r~P,wP); ↑(rP)`。底图 `P` 在启动沿锁存为全零或 `0x55555`，补码逐位反相。地址遍历覆盖全部四银行，同一周期任一时刻最多使能一银行。每遍为 163,840 次 SRAM 访问，再加最后一次读响应检查，从启动沿到完成沿间隔 163,841 个 SRAM 周期。在 40 MHz 约为 4.096 ms。生产可分别跑同质和棋盘底图，以提供不同的位邻接激励。实际版图桥连、耦合、保持、动态以及冗余覆盖范围由编译宏供应方故障模型和 ATE 试验确认。该算法会覆盖或改变已存样本，测试入口必须先冻结并弃置功能记录。通过时最终底图可能残留，失败和中止可留部分底图。

## 5. 复现命令

从交付目录根运行。令 `AD4080_VLT_ROOT` 指向 Verilator 安装目录或其 ASCII 路径别名，`PATH` 需含可执行的 `python` 和 C++20 编译器。`-Wno-DECLFILENAME` 对应现有 `result_store.sv` 同文件定义存储叶子。

```bash
ad4080_mbist_mdir=$(mktemp -d /tmp/ad4080-mbist-XXXXXXXX)
VERILATOR_ROOT="$AD4080_VLT_ROOT" "$AD4080_VLT_ROOT/bin/verilator" \
  --compiler clang -CFLAGS '-std=c++20' --binary --timing -j 2 \
  -Wall -Wno-DECLFILENAME --top-module result_store_mbist_tb \
  --Mdir "$ad4080_mbist_mdir" rtl/result_store.sv \
  memory/result_store_mbist.sv memory/result_store_mbist_tb.sv
"$ad4080_mbist_mdir/Vresult_store_mbist_tb"
```

控制器结构综合使用已配置的本机 Yosys 可执行入口。

```bash
yosys -Q -p 'read_verilog -sv memory/result_store_mbist.sv; hierarchy -check -top result_store_mbist; synth -top result_store_mbist -noabc; check -assert; stat'
```
