# `recip_q60` 布线阶段分析：密度超标

时间：2026-11-17　基线：`e4c6e31`

## 1. 现象

`recip_q60`（9,247 µm²，60 位倒数查表）的 RTL-to-GDS 运行 **21 分 52 秒**，仍停留在布线阶段。

```
Routed3/225 Partitions, Violations =2286
Routed4/225 Partitions, Violations =4420
Routed5/225 Partitions, Violations =5195
Routed6/225 Partitions, Violations =5426
Routed7/225 Partitions, Violations =7066
Routed8/225 Partitions, Violations =7066
```

## 2. 关键数据

| 指标 | 值 |
|:---|:---|
| 布局分区 | **1 × 1** |
| **布线分区** | **225 个（15×15）** |
| 21 分钟完成 | **8 / 225 = 3.6%** |
| 当前违规数 | **7,066** 且上升 |
| 综合耗时 | 约 6.5 分钟（已通过）|
| `Total number of DRCs`（早期） | 0 |

## 3. 换算

按 21 分钟完成 8 个分区的速度：

```
225 / 8 × 21 分钟 ≈ 590 分钟 ≈ 9.8 小时
```

**而且违规数在上升（2286 → 7066），说明不是"慢慢能收敛"，而是布线密度严重超标。**

## 4. 与 `wsum_v21` 的对比

| 模块 | DC 面积 | 布局分区 | 布线分区 | 结果 |
|:---|--:|:---|:---|:---|
| `dem_phase_gen` | 472.56 µm² | 小 | 少 | ✅ 3 分钟通过 |
| **`recip_q60`** | **9,247 µm²** | **1×1** | **225（15×15）** | ❌ **21 分钟 8/225** |
| `wsum_v21` | 102,202 µm² | 4×4 | 160×160 | ❌ 38 分钟未完成 |

**`recip_q60` 的布线分区数（225）与 `wsum` 的布局网格（160×160）是同一量级的复杂度。**

## 5. 根因

`recip_q60` 做 60 位倒数查表：

```systemverilog
// rtl/recip_q60.sv
// 从 2^60 / G 查表，G 是 16~64 范围的变量
```

60 位宽的运算 → 大量进位链与扇出 → 布线密度高 → 225 个布线分区。

**这不是配置问题，是 RTL 的位宽与结构决定的。**

## 6. 已通过的七个模块为什么没这个问题

| 模块 | 位宽 | 布线分区 | 结果 |
|:---|:---|:---|:---|
| `sched18` | 18~32 位 | 少 | ✅ |
| `adc2_capture` | 32~40 位 | 少 | ✅ |
| `acq_conv_ctx` | 32~64 位 | 少 | ✅ |
| `sar_evt_v21` | 6~12 位 | 少 | ✅ |
| `dem_phase_rr` | 小 | 少 | ✅ |
| `follower_rt` | 小 | 少 | ✅ |
| `dem_phase_gen` | 小 | 少 | ✅ |

**七个通过模块的位宽都 ≤ 64 位但结构简单；`recip_q60` 的 60 位倒数查表是高扇出结构。**

## 7. 结论

**`recip_q60` 的物理实现在当前配置下不可行**（布线需约 10 小时且违规上升）。

| 模块 | 状态 |
|:---|:---|
| 综合 | ✅ 通过（约 6.5 分钟）|
| floorplan / place_opt / CTS | ✅ 通过 |
| **布线** | ❌ **8/225 分区，7,066 违规，21 分钟** |
| Formality | 未跑 |

**与 `wsum_v21` 同属"物理实现不可行"，但程度较轻（`wsum` 连综合都没跑完）。**
