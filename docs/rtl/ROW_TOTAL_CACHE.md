# 配置期物理行和缓存

这项候选用于降低数字校正的组合归约开销。它保持顶层端口、系数精度、配置写入规则和16相位调度；实际PPA取舍以相同器件、工具、P5和25 ns约束的完整综合对照为准。它不是论文披露的片上学习算法。

## 为什么修改

有效P7对照中，列共享与除法借位改写组合的LUT由171,246增加到199,039，WNS仅从−17.426 ns改善到−17.112 ns。源码表达式减少不能证明PPA改善，见[原始对照](../evidence/20260930/vivado_complete_p7/README.md)。

系数在配置生效期间保持不变。逐样本重新计算每个物理行的全部系数和没有必要，因此装载器维护 `row_total[s] = sum(w_q[s][u])`，转换时仅将活跃物理行的总和相加。开关相关的 `on_tree`、采样dither列树及其物理叶子继续使用原系数。

## 状态契约

| 事件 | 系数表 | 行和 | written bitmap |
|---|---|---|---|
| reset | 全零 | 全零 | 全零 |
| clear_load | 保持数值 | 保持数值 | 清零 |
| 接受合法写 | 单项更新 | 同沿减旧值、加新值 | 对应位置置一 |
| 拒绝写或空闲 | 保持 | 保持 | 保持 |

clear后的第一次替换仍需减去保存的旧系数；不能用written判断旧系数是否为零。合法写的完整谓词仍由 `weight_store` 控制，运行中禁止修改。无效地址的 `selected_weight` 为零，顶层配置地址译码继续决定读回窗口。

每项合法系数小于2^47，因此一行U个单元的和严格小于U×2^47。内部 `ROW_BITS = 47 + $clog2(U)` 对支持的U=1…128成立，生产U=71需54位。向原64位和接口补零不丢失精度。该界限依赖装载器合法写守卫；直接使用任意48位系数的独立模块仍保留完整原算术域。

## 连接与综合边界

- `weight_store` 输出准确行和和选中旧系数；后者同时供替换更新及顶层配置读回，显式共用宽读选择路径。
- 顶层为 `recon_core` 开启 `P_USE_ROW_TOTALS`；该参数传到 `cal_weight_reduce`，从18行归约得到 `sum_W`。
- 直接驱动 `w_rom` 的独立模块保持默认关闭缓存，须明确连接新增行和端口。缓存打开时，调用者负责提供与系数一致的行和；真实生产链由同一装载器提供两者。
- 重复物理ID仍通过OR位图只计一行并报警；非法ID不激活行。采样dither仍引用显式驱动的系数叶子，不能随total树一起裁除。
- 跨模式信号声明移到首次使用之前，消除Vivado对legacy开关总线的先使用后声明告警；不改变位宽或时序。

该变换从1278项总和的1277次非平凡加法变为18项的17次，源级减少1260次加法，但增加972个生产配置状态位、行选择和替换加减法。配置路径也必须满足同一时钟的setup/hold，不能因为软件写得慢而加入false path或多周期豁免。全部物理系数仍可并行读取，不能声称已推断为单块SRAM。

## 验证及验收

`weight_row_cache_tb` 使用独立存储模型逐行重新求和，覆盖5种几何、完整最大合法权重装载、clear后重写、拒写、连续替换和非法地址。`cal_weight_reduce_ppa_tb` 在原有7种几何与1,430,848个样本上增加缓存实现，仍逐个对独立标量oracle检查；原旧公式及非缓存实现也保留。

负控分开检查两种责任：只损坏装载器的缓存更新，必须触发行和不变量失败；只改变送入归约器的行和而保持权重与oracle不变，必须触发缓存归约的数值失配。这能检测“缓存被错误维护”和“消费者根本没有使用缓存”两类问题。

完整生产结构回归还需核对18个slice、三种模式、配置读回、epoch取消，以及P5/P6/P7的15/13/11拍延迟与16拍请求间隔。每份日志须绑定实际源文件摘要；前代 `f028ec5` 的成功CI不等于新缓存候选通过。

综合面积下降也不等于时序闭合。最终验收需要有效完整综合网表、实际BUFG时钟布线、setup/hold/pulse width和约束覆盖检查，以及完整综合网表功能仿真。ASIC的640 MHz目标仍需实际标准单元库和物理实现，不能从FPGA数据推算签核。
