# I5 综合检查点 v2：块级数字不可用于时序结论

时间：2026-11-16　工艺：TSMC 28HPC+　工具：DC W-2024.09-SP3
基线：`a9fe12e`

## 1. 必须撤回的一条结论

之前写"recon 单独综合 slack +24.83 ns，说明时序充裕"。**这是错的。**

2026-11-16 重新导出路径详情后发现：

```
Startpoint: code_o_reg[19]
Endpoint:   code_o_reg[19]
data arrival time   0.15 ns
slack (MET)        24.83 ns
```

**8 条报告路径全部是 `code_o_reg[x] → code_o_reg[x]` 自环**，
没有一条经过除法器或乘法器。`0.15 ns` 只是触发器的 clk→Q 到 D 的
内部连线，即 D 端几乎没有组合扇入。

原因：`recon_v21` 是独立模块，端口全部无驱动。DC 在只读入模块、
不给输入驱动与负载时，会把整条数据通路**常量传播**掉，
只留下寄存器与常数连线。

加 `set_driving_cell` + `set_load` 后重跑，slack 变成 `+24.44`，
**但路径仍是自环，面积仍恰好是 22522.16 µm²** —— 说明常量传播并没有
被完全阻止，或者算术确实被优化掉了。

**结论**：
- `22522 µm²` 与 `+24.83/+24.44 ns` **都不能作为"算术满足时序"的证据**
- 块级面积可作为"综合能出网表"的存在性证据，但不能作为 PPA 结论
- 要得到可信的时序结论，必须用**有完整约束与驱动的顶层**

## 2. 层次对照实验：假设不成立

曾假设"顶层超时是因为跨层 ungroup 把除法器输入锥拉大"。

| 设置 | 结果 |
|:---|:---|
| 默认（ungroup 开） | 22 min 超时（rc=124），停在 `u_recon/code_o_reg[*]` |
| `set_ungroup false` + `set_boundary_optimization false` | **19 min 仍停在同一端点** `u_recon/code_o_reg[9]/D` |

**关掉 ungroup 没有解决**，跨层优化不是主因。该假设已撤回，
脚本里保留两行注释以便复跑对照，但默认恢复为默认 ungroup。
