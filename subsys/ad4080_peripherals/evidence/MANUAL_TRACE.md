# AD4080 数字外围逐模块手册审查

这份审查回答两个问题：AD4080 对外承诺了什么，我们的哪段代码确实实现了它。基线为 [外围提交 c912fd8](https://github.com/defineiocc02/20bit_SAR_ADC_Behaviour_Verification/commit/c912fd8a3796f0e6df4e163070a0797e5355a4e1)。芯片依据为 ADI 的《AD4080 Data Sheet》Rev. B，共 95 页，页码均为印刷页。核对的 PDF 的 SHA-256 为 `f08f2586dc82d5f583b42071b3570c06f1fe736d3053e15a559a47ed2841cbc1`。每条手册链接均可直接打开对应页。[ADI 原件](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf)

**最重要的差异在系统校正。** 图 96 的信号顺序为 ADC 码 → 加 OFFSET → 乘 GAIN → 滤波选择 → FIFO 或事件检测。冻结 DSP 先对原码作增益修正，最后加 OFFSET。两种次序在单位增益或零偏移时给出相同结果。将原码置零、OFFSET 写为 +1024、工程增益设为 129/128，两个整数输出分别应为 1032 和 1024。这个输入避开了饱和与半步舍入。[原图 96](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=64) · [逐拍回执](../calibration/rtl_verification.json)

**怎样读裁定。** “可认可”限于表格明列并已有独立观察的行为。“部分认可”表示同一模块还有明确的产品接线、接口时序或数值缺口。“不认可”表示已有反例，或所宣称的器件功能在产品入口不可用。“工程自定”表示有工程用途，但手册没有指定该内部结构、算法或工具。后两种均不得用来声称复刻了 ADI 内部实现。已知与手册不符的项目另列于末尾。

产品实例清单合并三个文件清单，得到 26 个设计模块的声明。另查两块单独验证的保护电路和原 DSP 目录中两个未被产品清单采用的模块。合计 30 个 RTL 模块，逐行列出。主机校准另有 3 个程序。33 行中，3 行的限定功能可认可，19 行部分认可，2 行有明确缺口而不认可，9 行属工程自定。外围目录 34 份 SV 源中的 25 个台架、性质模块及 FPGA 原语模型另列；数字转换组和模拟宏的责任也在末尾交代。[服务清单](../integration/files.f) · [记录清单](../integration/readback_files.f) · [产品清单](../integration/product/rtl.f) · [职责清单](../interfaces/function_ownership.csv)

## 8. 哪些功能没有芯片手册依据

- **结果 CRC。** 图 87、88 支持 SPI1/SPI4 图示访问前缀；图 89 画出单路 LVDS 的 24 位尾。没有获得与不同数据/长度对应的真实 CRC24 金样，也没有从 Rev. B 找到多项式、初值、反射、终异或及完整覆盖范围。工程余数 0x71F3EC 只属于已声明的测试参数。ADI 主机固件和 FPGA 原源码可复核其读帧动作；离线 CRC 程序、合成例和理想原语属于测试工具。[手册图 87、88](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=59) · [手册图 89](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=60) · [CRC 采集与判别](../io/adi_crc/README.md) · [ADI FPGA 实测](../io/adi_receiver/README.md)
- **电源和工厂存储。** 手册给出双 LDO 内供和外供接法、核心/参考电压监测、上电后 300 µs 初始化和出厂校准。待机 100 µs、睡眠 180 µs 的唤醒时间之后，图 44 另画没有定值的恢复时间；精度恢复不能用逻辑定时器盖章。查 95 页可检索正文和相关图，能定位只读 ROM CRC/ECC 位，找不到 OTP 工艺、启动镜像、March 算法、修复或扫描资源的器件披露。数据手册的 ROM、配置 CRC8、记录 CRC24 是三个对象。[p.23 内供图 38](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=23) · [p.24 外供和 POR 图 39、40](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=24) · [图 44](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=27) · [表 47](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=83)
- **版图和面积。** Rev. B 给出 49 球 CSP BGA、引脚及外部供电连接；手册没有给 die 尺寸、工艺、各数字功能面积、小 SRAM 的用途、OTP 区大小或宏 LEF。规划 GDS、四银行排布、面积预算、PDN 通道与 SRAM 接收脚本都是项目交付。不能凭封装长宽反推出裸片占比。论文/讲稿原型的 Digital 框可以单列为原型量测，不能填为 AD4080 商品芯片模块面积。[表 6 引脚](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=10) · [封装页](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=95) · [项目面积和宏资料门](../budget/README.md)
- **转换核与模拟宏。** 36 项职责中，片组调度、Flash/SAR 事件跟随、双 SADC、DEM 选元、RDAC、dither 生成/预置与扣除、单元权重训练与应用、余差路径、ADC2 量化及其归属共 12 项属于转换、模拟或相应的片外权重估计。Rev. B 图 31、32 支持 SAR 与连续采集框架，未披露本仓的选片、扰动、权重或内部端口细节。系统 OFFSET/GAIN 是另一个环节。登记在此处的转换核沿用既有功能组，审核结论止于交接边界。[架构图 31、32](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=19) · [36 项职责逐条归属](../interfaces/function_ownership.csv)
- **签核和测量。** `4×4096×20`、CDC 深度、常开时钟上界、Pad 位置与面积是设计参数。要认可器件等效性，还需要实物在同一时基下的 CNV/CLK/GPIO/串行位流、增益与 OFFSET 联合扫描，以及供应方宏和 PVT 资料。布图、GF(2) 分析、no-OS/HDL 联测和既有 29 组回归各自回答不同的问题。[物理与逻辑未闭合项](peripheral_open_items.csv) · [本项目回归回执](peripheral-review.json)

## 9. 判据、待办与复核方法

**需要分别处理的现场问题。**

1. **[需仓主决策] 校正单元的寄存器语义。** 片外实测增益表已按图 96 给出乘前 OFFSET 初值，工程 K/SHIFT 仍准确重现现用 RTL。若要求产品达到手册，应由该 DSP 的维护者在同一实现上统一 RTL 与整数参考，让 +1024 的判别向量过关，再用正、负 OFFSET 和多档 GAIN 做联合验证。板上绝对精度另需实测 VREF 及已标定输入。[手册图 96](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=64) · [开项与解除条件](peripheral_open_items.csv)
2. **[需仓主决策] 首先交付哪几种产品工作模式。** 若承诺全手册接口，需要把 0x15–17 的实际选择、连续单/双 lane、采后 SPI、滤波同步与有效就绪、配置到真实电源命令都接入同一个产品顶层，再用主机写寄存器、观察 GPIO、完整读到最后一位。外供 IOVDD 的待机读 FIFO 有专门条件；单路 LVDS 记录回归无法替代它。还应覆盖 CNV 停走、字间连续性与模式 11 的整记录读回。[表 11](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=26) · [数据接口图 51、52](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=33)
3. **核实事件语义与故障报告。** p.55 图 83 区分越阈后的活动电平 ALERT 和写 1 才清除的粘滞状态；p.56 图 84、85 对迟滞电平和路由信号另作描述。当前回窗后实得 HI_DTCT=0、ALERT_N=1、HI_STATUS=1。RTL 对阈值相等采用高端 ≥、低端 ≤，W1C 同沿优先清除粘滞位，事件脉冲可仍然产生。须在同一 CNV 波形上分别采 GPIO、CSR 和 FIFO 触发。冷启动从未提供 REFIN 时测试字应停；先提供再移除时测试字可用。服务壳目前没有跟踪这种历史。[图 83](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=55) · [图 84、85](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=56) · [冷启动参考条件](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=24) · [回窗反例](../interfaces/control_review/validation.txt)
4. **[需仓主决策] 未披露的内部实现。** OTP 影子表、March C−、四银行 SRAM、跨域 FIFO、真实宏、floorplan 与测试覆盖可按本项目独立指标验收。若要标为 AD4080 器件实现，需要另外取得适用的直接证据。现有公开资料只支撑表中列出的外部行为。[功能/接口图 1](https://www.analog.com/media/en/technical-documentation/data-sheets/ad4080.pdf#page=1) · [工程功能矩阵](../interfaces/function_ownership.csv)

验证专用清单：`BUFIO`、`BUFR`、`IBUFDS`、`IBUFGDS`、`IDELAYCTRL`、`IDELAYE2`、`ISERDESE2`、`ad4080_ddr_edge_words_properties`、`ad4080_ddr_edge_words_tb`、`ad4080_fifo_record_framer_tb`、`adi_receiver_tb`、`calibration_verify_tb`、`control_review_tb`、`noos_spi_rtl`、`peripheral_readback_link_tb`、`peripheral_services_tb`、`pinned_fifo_contract_tb`、`power_bridge_tb`、`result_store_mbist_tb`、`store_tb`、`tb_ad4080_peripheral_product`、`tb_ad4080_pwr_supervisor`、`tb_ad4080_result_transport`、`tb_dsp_path`、`tb_otp_shadow_loader`。

从仓库根运行。第一条按声明和文件清单检查覆盖、源码目标及手册定位；第二条以器件一致性为条件，遇部分认可或不认可时预期退出 2。这个检查器能发现漏列模块和缺少出处，逐图阅读及行为裁定仍由审查者负责。

```sh
p=subsys/ad4080_peripherals
node "$p/verify/check_manual_trace.mjs" --check-local
node "$p/verify/check_manual_trace.mjs" --require-device-match
```

做模块复测时，校准对应 `adctoolbox_host / adctoolbox_rtl / product_calibration`；滤波、事件与 GPIO 对应 `dsp_data / dsp_control / adi_noos`；FIFO 和实体存储对应 `store / queue_port_full_depth / product_binding`；输出接口对应 `edge_words / record_frame_0 / record_link / transport / adi_receiver`；启动与自测对应 `power / otp / mbist / services`。同一命令可以重复传 `--case`。含官方互操作测试时，以 `--fetch-adi` 获取固定官方源或传入已校验的本地源。完整工具环境与 29 组结果见[回归入口](acceptance.md)。

已有 Verilator、C++ 编译器与安装了校准依赖的 Python 时，可重跑工程算术与图 96 判别，并保存机器可读结果。最后一条在原 DSP 仍给出 1024 时返回 2。

```sh
p=subsys/ad4080_peripherals
python -m pip install -r "$p/calibration/requirements.txt"
python -B -m unittest discover -s "$p/calibration" -p 'test_*.py'
python -B "$p/calibration/verify_rtl.py" --repo . --out /tmp/ad4080-order.json --require-manual-order
```
