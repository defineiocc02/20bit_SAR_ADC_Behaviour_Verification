# 工程代码维护约定

适用于当前 Python 行为模型、SAR/DSP 生产 RTL、测试入口及当前说明文档。
这些约定用于功能可维护性和可复验性；工艺签核由对应工具与电路证据证明。

## 需求和接口

- 先写清本次需求的输入、输出、模式、合法范围和异常结果，并映射到实现及独立验证。
  论文披露、专利可选实施例、工程假设和项目扩展分别记录，不能互相替代。
- Python/RTL 对拍应明确配置、物理单元顺序、位序、码制、样本 ID、延迟和舍入。
  当前结构对照合同见 [ADR 0021](adr/0021-structural-contract-calibration.md)；
  其他行为配置保留各自的适用域。
- 公共 Python 字段、RTL 端口、参数、寄存器地址及固定向量格式属于兼容接口。
  改名或改变行为前检查全部调用方、约束、工具脚本和测试，不能只改声明。

## 命名和单位

- Python 函数和一般变量用 `snake_case`，类型用 `PascalCase`，常量用 `UPPER_CASE`。
  方程中的 `C_f`、`G_R`、`A`、`B` 等符号可以保留，但在接口或相邻公式中定义其
  物理含义、单位与形状。局部循环索引可以简短；跨模块数据应表达对象和用途。
- 新增数值接口优先写出单位后缀，如 `_v`、`_s`、`_hz`、`_f`、`_c`；码用 `_code`，
  物理选择用 `_mask`，样本标识用 `_sample_id`。已有数学符号不为形式统一而批量改名。
- RTL 延续所属模块现有命名；时钟、复位、使能、握手和标识必须含义稳定。
  `_n` 表示低有效，`_valid` 表示该拍数据有效，`_ready` 仅在确有接受能力语义时使用。
  不把脉冲、每笔状态和粘滞状态共用一个名字。
- 定点接口写清总位宽、符号、二进制小数位、归一化参考和饱和方式。
  仅写 `_q` 或 “Q32” 不足以定义一个可互换的格式。

## 注释和模块合同

- 模块头说明职责与边界、必要的文献位置或推导、输入/输出单位和适用模式。
  注释说明设计理由、约束和例外；历史故障过程放入 ADR 或有版本的证据记录。
- Python 公共接口说明参数、返回值、数组形状、非法输入、状态修改和随机源。
  随机模型使用显式 `np.random.Generator`；种子、物理失配、噪声及调度的职责要明确。
- RTL 合同说明时钟域、复位置位/释放、同沿优先级、启动/接受条件、结果延迟及吞吐，
  并区分正常、丢弃、取消、溢出和恢复路径。
- 有符号运算和常量宽度显式定义，转换、截断、舍入、饱和及除零行为有明确依据。
  非法尺寸或模式在真实入口报错，不静默填零或降级到另一种算法。
- 引用的文件、测试符号、章节和命令必须存在。单次夹具通过应写出条件，不能提升为
  所有模式、模拟性能或工艺时序已验证。

## 来源与完成状态

- 顶层 `Config` 字段在 `PARAM_GRADES` 中登记来源；嵌套参数由所属接口说明来源和假设。
  派生结论保留所有依赖，拟合值产生的结果不能写成无参数预测。
- `mechanism_inventory.json` 的当前缺口与关闭记录应一致。已关闭项保留历史原因与
  验证入口，不继续写成当前“未实现”；未完成项保留可定位的条件和解除标准。
- `PASS`、`FAIL`、`NOT_RUN`、`BLOCKED` 各自表达实测通过、实测失败、未执行和有阻碍。
  字段范围声明、静态检查、功能仿真、形式证明和电路/工艺证据分别记录。

## 验证与提交

- 先冻结基线并保护未提交文件。改动聚焦当前需求；重构不混入未说明的算法变化。
- Python 运行相关测试、ruff 和类型检查；信号路径修改还需完整 `adi-run-all` 验收。
  RTL 运行实际 lint、相关自检 testbench 和协议/边界测试；影响其他验证层级时更新其状态。
- 参考模型应在算法、算术或数据来源上具有独立性。记录输入、配置、代码版本、工具版本、
  输出和关键文件哈希。数值或固定向量变化说明原因；保留可回滚的基线。
- README 保留四块工作说明：转换控制、DEM/dither 与交织、电容校准重构、系统 DSP 输出。
  图注列明数据来源、条件、单位和验证范围；示意数值、行为数据、RTL 结果与芯片测量清楚区分。
- 长任务留下检查点。提交说明写明改变的行为、相关验证及未完成的实际条件，不以命名或注释
  改善代替功能证据。
