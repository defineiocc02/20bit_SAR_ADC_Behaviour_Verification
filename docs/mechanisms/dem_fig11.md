## ② 原理与事件过程

沿 Fig.11：

1. **采样**：每片的主阵列与子阵列底板接输入，顶板存 `x`。
2. **转换**：高 4 位 `B0–B3` 走 15 个 2C 温度计；`B4` 在**组内 16 个 1C 中选 8 个**；
   `B5–B8` 走二进制子阵列（8/4/2/1），经桥 C（β=1/17）耦合到主节点。
3. **两个 shuffler**：横向在 15 列内旋转起点；纵向在 16 个 1C 内旋转选择窗口。
   论文再加第三个维度：18 片里选 8 片。
4. **DEM 的作用点**：不是改变权重，而是改变"同一码由哪些物理单元实现"。
   所以它压的是**固定失配造成的码相关误差**，代价是把失配摊成逐笔噪声。

## ③ 当前实现映射

| 专利原图（待核对） | 当前模型对象 | 函数 | 关键变量 | 主链调用位置 |
|:---|:---|:---|:---|:---|
| Fig.11 主阵列 15×2C + 2×1C | `SplitChip.C_main`（17 个/片） | `dac_arch.SplitChip` | `C_main` | `defaults.DefaultModel` |
| Fig.11 子阵列 8/4/2/1/1 | `SplitChip.C_sub`（5 个/片） | 同上 | `C_sub` | 同上 |
| 桥接 C（β=1/17） | `SplitChip.C_bridge` | `dac_arch.split_capacitance_coefficients` | `beta` | 同上 |
| 横向 shuffler（15 列） | `fig11_masks` | 起点 `(h + 物理ID) % 15` | `state.horizontal` | 未接主链（仅测试与文档） |
| 纵向 shuffler（8/16） | `fig11_masks` | `(2·组内位置 + unit + v) % 16 < 8` | `state.vertical` | 同上 |
| 子阵列二进制（不可旋转） | `fig11_masks` | `B5–B8` 直通 | `code >> (3-unit)` | 同上 |
| 片选 8/18 | `round_robin_plan` | 连续窗互斥轮转 | `plan.conv/acq` | `pipeline_engine` |
| 保留列（reserved column） | `control.fig11_dem.map_fig11` | 相位 15 → 哑列，窗口跳过 | `reserved_column_hit` | 旧控制路径（掩码测试） |
| **跨片分配规则（Fig.19–21）** | **未实现**（用调度器的固定窗口替代） | — | — | — |
| 主线工程拓扑 63+8 | `unary_rotation_masks` | 主段 `(h+pid)%63`、子段 `(v+pid)%7` | 同上 | `run_p4_ablation._run` |

**必须说清的三件事**：

1. `fig11_masks` 的横向按**物理 ID** 旋转、纵向按**组内位置**选 8/16。这个不对称是刻意的：
   纵向若按物理 ID 取模，18 片池会选出 9~10 个 1C 单元，B4 的名义权重当场变。
2. `unary_rotation_masks` 是**工程拓扑**，不是 Fig.11。它的两段都是 unary，所以可以整段旋转；
   Fig.11 的子阵列是二进制权，**旋转即改权重**，所以不能旋转。
3. 论文的"3 维 DEM"在本仓库里被拆成"掩码两维 + 调度一维"，分别在 `dem3d` 与 `timing` 两个模块，
   **不是同一个函数**。

## ④ 一个真实样本（`docs/mechanisms/data/one_sample_trace.json`）

样本 97，DEM 状态 `horizontal=41, vertical=3`，物理片 `[2,3,4,5,6,7,8,9]`，粗码 129：

| 量 | 值 |
|:---|:---|
| 每片主单元选通数 | 16（16×8 = 128，对应 63+8 池的 `code//8 = 16`） |
| 每片子单元选通数 | 1（`code%8 = 1`） |
| 片 0 的主单元索引 | 43…58（起点 `(41+2)%63 = 43`，连续 16 个） |
| 片 0 的子单元索引 | 5（起点 `(3+2)%7 = 5`，取 1 个） |

读法：`horizontal=41` 与物理片 2 相加得 43，说明**旋转是按物理 ID 而不是按槽位**；
若按槽位，同一片换到别的槽位就会换一批单元。

## ⑤ 同条件开/关对比

| 量 | 无 DEM | 有 DEM | 条件 |
|:---|:---:|:---:|:---|
| INL（σ=0.1%，32 次重复） | **24.5 LSB20** | **6.2 LSB20** | 256 电平，63+8 池 |
| INL 的失配斜率 | 23 372 ppm/σ | **6 327 ppm/σ（0.27×）** | 5 个 σ 点 |
| 低码主单元覆盖 | 32/63（修前） | **63/63** | 码 8、单片、一个相位周期 |
| 子单元使用（码 1、单片） | 756/756/504×5（3:2） | **36×7（严格相等）** | 9072 笔联合周期 |
| NSD | 20.91 nV/√Hz | 26.98 nV/√Hz（+29%） | 同池同 seed |

**代价必须一起说**：DEM 把 INL 压到 0.25× 的同时把噪声抬高 29%。
只报前者等于隐瞒成本。

## ⑥ 差距与下一步

| 差距 | 是否影响结论 | 下一步 |
|:---|:---:|:---|
| 保留列**已建模，但与新实现的相位语义不同** | 影响"两套实现是否等价" | 旧路径相位 15 合法并标记命中；新路径用 `%15` 直接旋转。两者在 slot==物理 ID 且 v=0 时逐位相同，v≠0 时因 `-v`/`+v` 不同——由 `tests/unit/test_fig11_vs_dem3d.py` 钉住 |
| **跨片分配用固定窗口** | 影响与论文"随机 8/18"的等价性 | 把调度器接入 `fig11_masks` 的第三维，或明确声明是工程替代 |
| Fig.11 的 8/16 按位置选 | 影响"物理片级均匀"的最优性 | 若要做按 ID 选择，需先解 B4 权重的守恒问题 |
| DEM 只在掩码层，未进 RTL | 影响硬件结论 | RTL 侧仍是旧的 `unit_therm`，不宣称 3D DEM |
| 子阵列二进制不可 DEM | 影响低频码的失配平均 | 记录为拓扑固有限制，不做补救 |

**验收口径**：本篇支撑"两维掩码 + 第三维调度、按物理 ID 旋转、名义守恒、逐片覆盖、
保留列相位合法"；**不支撑**"复现了 Fig.19–21 的跨片分配规则"——那一条仍未实现。
另外两套 Fig.11 掩码实现（旧 `map_fig11` / 新 `fig11_masks`）的差异已用测试钉住，
但**尚未合并成一套**。
