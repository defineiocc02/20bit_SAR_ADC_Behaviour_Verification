# D2 量化器 / Follower 接口规格（证据索引版）

## 0. 本轮更正

**撤回：**"1 个 Flash 事件 + 6 个 SAR 事件 = 7 个事件"的冻结要求。

理由：论文与专利都没有公开**恰好 6 次后续比较**及其事件时刻。
`9 − 3 = 6` 只是无冗余 9 位二进制模型下的算术推导，属**工程推导**。

**保留：**3-bit Flash、9-bit 前级量化、Flash 先定最高 3 位、双 SADC 交替。

### 关键澄清：40 MS/s ≠ 每事件 25 ns

论文提到独立量化器完成一次转换约 **7 ns**，并用两个量化器避免干扰 RDAC 采样。

因此：

```
9 × 25 ns = 225 ns  只是当前同步 RTL 测试协议的吞吐率
不代表论文采用 9 个 25 ns 的判决周期
```

**也不能因为改成 7 个事件就宣称达到 40 MS/s。**

## 2. 应冻结的三组接口

### 2.1 Flash 结果接口

```systemverilog
flash_valid_o        // 该拍的 flash_code 属于本笔事务
flash_code_o [2:0]   // 最高 3 位判决
flash_tag_o  [...]   // 事务身份
```

**当前状态：未实现。** 现有 RTL 没有 Flash 单元，最高 3 位由 SAR 试探得到。

### 2.2 SAR 已决事件接口

```systemverilog
sar_valid_i        // 一位已决
sar_bit_i          // 已决码位
sar_index_i [3:0]  // 该位在原码中的位置（0..8）
sar_qid_i          // 量化器 ID（A/B 两套交替）
```

**当前状态：** 已实现 `ev_valid_i / ev_bit_i / ev_idx_o`，
但**位置由内部递增推定**（第 idx 个事件对应第 8-idx 位），
且**只有一个量化器**，没有 `sar_qid_i`。

### 2.3 Follower 输出接口

```systemverilog
ev_mask_o [159:0]     // 8 片 × 20 单元物理开关
ev_ids_o  [39:0]      // 冻结的物理片 ID
ev_mask_valid_o       // 该事件产生了合法命令
ev_err_o              // 越界/异常
```

**当前状态：已实现并通过 5544 事件对拍。**

## 3. 双 SADC 与共享 Flash：未实现

论文 Fig.9.8.1 画的是**上下两套交替工作的 SAR 量化器**，Flash 可共享。
当前 RTL 只有**一套**事件通路，`ev_mode_i` 也只是把它接到 E1。

**因此不能说当前 RTL 对应论文 Figure 9.8.1 的结构。**

若要实现，需要：

| 项 | 内容 |
|:---|:---|
| 两套 sDAC + 比较器 + SAR 控制 | 独立失配、独立相位 |
| 交替调度 | 相邻样本分给 A/B，与 RDAC 的 8 采 8 转对齐 |
| 共享 Flash | 一次 Flash 结果分发给两个 SADC |
| Follower 双源 | `sar_qid_i` 决定用哪一路已决事件驱动 RDAC |

## 4. 当前 9 事件模式的定位

**这是功能验证模式，不是论文的实际控制器。**

保留它的价值：证明"已决事件 → DEM → 物理 mask → 共享重构"这条链正确。
但它：

- 不含 Flash
- 只有单量化器
- 事件数固定 9（8 温度计 + 1 子阵列），是**本工程的码结构**，不是论文时序
- 未约束事件时钟，吞吐率 4.44 MS/s

## 5. 不受影响的模块

**D3 DEM / D4 Dither / D5 权重校正的数学与 RTL 不改。**
D2 接口调整后只需重跑对拍：

- 420/420（D5 模块级）
- 8509 笔（整码顶层）
- 5544 事件（事件通路）

## 6. 后续动作

1. **不实施**把事件数改成 7 的改动（证据不足）

3. Flash 与双 SADC 属架构新增，**需单独评估后再动**
